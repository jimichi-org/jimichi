# Термины

[English](../en/GLOSSARY.md) | Русский

| Термин | Значение |
|---|---|
| Ячейка | единица передачи постоянного размера, 512 байт |
| Слой | уровень шифрования, снимаемый одним узлом цепочки |
| Хоп | переход между соседними узлами цепочки |
| Цепочка | узлы, через которые идёт сообщение, по умолчанию три; клиент выбирает их из своего списка узлов |
| Список узлов | статический список узлов, из которых клиент выбирает цепочки; до построения цепочки проверяется каждый узел списка, комплект которого отдал вход; при случайной цепочке вход может не отдать не больше -missing узлов (по умолчанию один, но не больше, чем в списке сверх -hops), и они в цепочку не попадают |
| Вход, середина, выход | места узла в цепочке: вход это первый узел и единственный, с которым соединяется клиент, середина между входом и выходом, выход это последний узел: он снимает последний слой и на стенде возвращает сообщение обратно по цепочке (эхо); доставка клиенту-получателю в плане ([#18](https://github.com/jimichi-org/jimichi/issues/18)) |
| Подставной узел | узел, который принадлежит нарушителю: скомпрометированный или подставленный с валидным сертификатом |
| Постоянная цепочка | первые узлы списка в порядке списка вместо случайного выбора, для измерений, которым нужен известный путь |
| Эфемерный ключ | ключ, действующий одну сессию; его буфер после неё зануляется, а копии, сделанные библиотеками, остаются на куче до повторного использования этой памяти (CRYPTO, "Известные дыры") |
| UKM | множитель VKO, привязывающий согласованный секрет к сессии; в наборе ГОСТ это первые 8 байт хэша транскрипта |
| Транскрипт | открытые данные одного обмена ключами в однозначной раскладке: версия, параметры обмена, открытые ключи сторон и, при аутентификации узлов, ключ личности узла (CRYPTO, "Вывод ключей") |
| Контекст ключа | хэш транскрипта вместе с набором (Context); входит в каждое согласование и в каждый вывод ключа, без него провайдер ключ не выводит |
| AEAD | шифрование с аутентификацией и связанными данными |
| Фоновый трафик | ячейки без полезной нагрузки, которые отправляются, чтобы замаскировать моменты реальной передачи: поверх сообщений или в пустых слотах расписания постоянной скорости; насколько они маскируют, измеряется, а не предполагается (EXPERIMENT, блок 1) |
| Заполнение канала | кадр, который узел отправляет соседу на пустом тике своего расписания; сосед его отбрасывает |
| Отправка по своим часам | узел шлёт по одной ячейке на тик собственного таймера, а не в момент прихода |
| Заполнение | добавление байтов до постоянного размера ячейки |
| Атака корреляции | связывание отправителя и получателя по таймингам и объёмам |
| Развязка | свойство, при котором наблюдатель не может связать отправителя и получателя |
| Прямая секретность | компрометация долговременного ключа не раскрывает прошлые сессии |
| Шаблон KK | рукопожатие, в котором обе стороны заранее знают статические ключи друг друга: каждое из двух сообщений несёт свежий эфемерный ключ и подмешивает согласования с ключами собеседника; в сквозном слое это записи kk1 и kk2 (CRYPTO, "Сквозной слой") |
| Хэш-ратчет | цепочка ключей одного направления: каждый шаг выводит ключ записи и следующий ключ цепочки, а прежний стирает, поэтому компрометация текущего ключа не раскрывает прошлые записи; восстановления после компрометации он не даёт |
| KCI | подмена при компрометации ключа (key compromise impersonation): тот, кто знает закрытый ключ стороны, выдаёт себя этой стороне за другую; в KK так подделывается kk1, и правила сессии сводят это к сбросу сессии, которой нет, неподтверждённой или устаревшей |
| Якорь доверия | открытый ключ УЦ, которому клиент доверяет заранее, в виде строки `<набор>:<base64>` |
| Сертификат узла | подписанная УЦ запись, которая связывает имя, адрес и ключ подписи узла на срок действия |
| Ключ подписи узла | долговременная пара подписи узла (ключ личности): подписывает запрос сертификата и дескриптор, в согласовании не участвует; при аутентификации узлов его открытая половина входит в транскрипт установки и канала узла |
| Онион-ключ | ключ узла, с которым клиент согласует секрет слоя при установке цепочки; с ротацией узел меняет его по эпохам |
| Ключ канала | открытый ключ узла (LinkPub в дескрипторе), который инициатор канала к этому узлу подмешивает в рукопожатие: клиент для своего входа, узел для следующего узла цепочки |
| Дескриптор узла | подписанная ключом подписи узла запись: хэш сертификата, ключ канала, онион-ключ, эпоха и короткий срок |
| Эпоха онион-ключа | номер онион-ключа узла в его дескрипторе: 0 у первого ключа процесса, на единицу больше после каждой ротации; ключ канала при этом не меняется |
| Льготный период | время, которое узел ещё держит заменённый онион-ключ: срок дескриптора плюс допуск часов после ротации |
| Комплект узла (bundle) | сертификат и дескриптор узла в одном JSON-объекте, который узел отдаёт клиентам |
| Ростер оператора | список имён и адресов узлов, которым оператор разрешил выдать сертификат |
| Ростер узла | якорь с именами и адресами узлов одной выдачи, который получает каждый из них; узел продолжает цепочки только на узлы ростера |
| Зеркало дескрипторов | собственный комплект узла и комплекты тех узлов ростера, которые у него сейчас есть; узел отдаёт их на /descriptors, чтобы клиент обращался только ко входу; узел ростера не входит в зеркало, пока его комплекта нет, комплект ещё не начал действовать по часам узла или до его истечения осталось меньше запаса зеркала (ARCHITECTURE) |
| Выдача сертификата | УЦ проверяет подписанный запрос узла с nonce, выбранным УЦ, по ростеру оператора и подписывает сертификат |
| Порядок counter | на каждом канале узел принимает только counter на единицу больше предыдущего, всё остальное закрывает цепочку; клиент так же принимает номера ответов; защита от повтора |
| Дамп памяти | снимок памяти процесса; сценарии извлечения ключей, которые будут в нём искать, в плане ([#24](https://github.com/jimichi-org/jimichi/issues/24)) |
| ROC, AUC | кривая и площадь под ней, мера успешности атаки корреляции |
| Бутстрэп | способ построить доверительный интервал по выборке |
