# Программа исследования

[English](../en/EXPERIMENT.md) | Русский

Работа отвечает на один вопрос: **какой ценой в полосе и задержке покупается стойкость к анализу
трафика в трёхузловой цепочке с постоянным размером ячейки, и где эта стойкость перестаёт
работать**. Остальное подчинено ответу на него.

Каждый прогон воспроизводим: в отчёт пишутся конфигурация, зерно генератора, версия кода и время.
Результаты в artifacts/, графики строятся из тех же файлов.

Реальные клиенты запускаются в несвязанные моменты, поэтому в обвязке lab расписание каждого клиента
получает случайную фазу из зерна прогона. Клиенты, запущенные подряд, тикали бы почти в одной
фазе и давали атаке ничьи, которых в настоящей сети нет. Окно наблюдения тоже открывается в
случайный момент относительно расписаний: иначе последний запущенный клиент тикал бы в такт окнам.

Зёрна: из базового зерна серии выводится зерно каждого повтора, из него отдельные потоки для фаз
клиентов и для интервалов каждого потока (splitmix64). Соседние повторы и потоки не делят случайных
последовательностей. Цепочки, которые выбираются в блоке 3, берутся из своего потока, выведенного из
зерна так же. Зёрна обучающих прогонов блока 7 выводятся из базового зерна своим потоком, а сдвиг и
перестановка меток нулевого уровня из своих потоков зерна прогона. Фазы часов узлов берутся не из
зерна, а из генератора самого узла, как в настоящем развёртывании. В каждой строке отчёта записаны
конфигурация, зёрна, ревизия кода и загрузка хоста до и после прогона для этих наборов трафика.
Блок 4 записывает своё расписание и окружение, без секретов из зерна.

## Модели нарушителя

Обозначения используются во всех таблицах результатов. Пока измерены: П1 атакой корреляции числа
ячеек (блок 1) и выбор цепочек для П4 (блок 3). Серия временной метки П3 измерена на записанной исторической ревизии
(блок 2). В блоке 4 реализована узкая кооперативная проверка
ключей ячейки клиента с завершённой описательной серией, без проверки всей модели П5; широкие
эксперименты П5 и П6 остаются в плане. Для П2 различитель ячеек реализован (блок 7), его серия
остаётся в плане.

| Код | Нарушитель | Что видит и может |
|---|---|---|
| П1 | Пассивный на обоих плечах | временные метки и размеры пакетов на участках клиент-первый узел и последний узел-получатель. Клиент-получатель есть (клиент -peer через mailbox, ARCHITECTURE), но блок 1 по-прежнему измеряет эхо-топологию: наблюдатель обвязки берёт вместо дальнего плеча канал к последнему узлу, а последний узел возвращает сообщение эхом. Измерение топологии разговора, два входа и mailbox, в плане ([#47](https://github.com/jimichi-org/jimichi/issues/47)) |
| П2 | Пассивный на одном плече | то же, но только на входе цепочки |
| П3 | Активный сетевой | задерживает, дублирует и отбрасывает ячейки, встраивает временную метку в поток |
| П4 | Компрометация узлов | полный доступ к части узлов, включая память процесса: к одному или двум из трёх узлов цепочки, к k из N узлов, из которых клиент выбирает цепочки |
| П5 | Локальный на устройстве | доступ к памяти и диску узла или клиента во время работы и после |
| П6 | Локальный с историей | несколько снимков файла контейнера в разные моменты времени |

Нарушитель знает устройство системы и исходный код. Стойкость держится на ключах и статистической
неразличимости, а не на секретности реализации.

## Метрики

### Связывание отправителя и получателя

| Метрика | Определение | Зачем нужна |
|---|---|---|
| ROC AUC | площадь под кривой ошибок атаки связывания; пара с равными оценками у верной и неверной пары считается за половину | сводный показатель, сравним между конфигурациями |
| Точность top-1 | доля входных потоков, у которых выходной поток с наибольшей оценкой их собственный; если наибольшую оценку делят k выходных потоков и свой среди них, поток даёт 1/k | что получает нарушитель, который выбирает лучшую пару |
| TPR при FPR 0.01 | доля верно связанных пар при фиксированной доле ложных | атака опасна именно в области малых ложных срабатываний |
| Точность при базовой ставке | TPR π / (TPR π + FPR (1 - π)) в рабочей точке FPR 0.01 с TPR при ней (строка выше): доля верных среди пар, которые нарушитель называет связанными, когда верна доля π пар-кандидатов. Для связывания π = 1/F, F это число потоков в сети, о которой делается вывод; сводка приводит точность и при F стенда. Это пересчёт, а не замер: TPR и FPR, измеренные на стенде, считаются теми же при F потоках. Сводка считает TPR по оценкам всех чистых прогонов конфигурации вместе, с одним порогом, и приводит (pooled_negatives) число неверных пар, на котором стоит FPR. Нарушитель, который получает ту же TPR при меньшей FPR, получает и точность выше. Не определена при π вне (0, 1) и без положительных решений (TPR π + FPR (1 - π) = 0). Пример: TPR 0.9, FPR 0.01 и π = 1/1000 дают 10/121, около 0.083 | защищает от подмены понятий: при тысяче потоков AUC 0.9 для нарушителя почти бесполезна |
| Ранг истинного отправителя | для каждого выходного потока число входных, чья оценка не ниже, чем у верного (верный тоже, ничья считается целиком), среднее по выходным потокам прогона: 1, если верный единственный лучший, F при ничьей всех. Это не множество неразличимых кандидатов: нарушитель их различает, но ни одного не отбросит, не рискуя потерять верного. Пример: оценки 0.9 у верного и 0.95, 0.9, 0.3 у остальных дают 3 | наглядно на защите |
| Степень анонимности по рангам (оценка сверху) | r это место верного входа среди F входов выходного потока по убыванию оценки; если его оценку делят ещё t входов, каждое из t + 1 мест получает 1/(t + 1); оценки сравниваются точно, как в точности top-1. q_r это доля выходных потоков с местом r по всем чистым прогонам конфигурации вместе, H = -сумма q_r log2 q_r по r в битах, d = H / log2 F. Нарушитель, который знает только порядок оценок и судит о каждом выходном потоке отдельно, приписывает входу на месте r вероятность q_r. Нарушитель, который видит сами оценки, знает не меньше, поэтому против этих оценок анонимность не больше d: это оценка сверху, а не мера сильного нарушителя. Нарушитель, который учитывает, что каждый вход связан ровно с одним выходом, и смотрит на всю матрицу оценок, может знать больше, и против него анонимность не выше, d ограничивает и её. Малая d показывает малую анонимность, d около 1 показывает только, что эта атака узнаёт мало. H по N выходным потокам занижена, в первом порядке на (K - 1)/(2N ln 2) бит, K это число мест с q_r > 0, поэтому рядом приводится H с поправкой Миллера-Мэдоу, не выше log2 F; остаток смещения у неё мал и бывает любого знака, а около log2 F ограничение оставляет её чуть ниже; по одному прогону H не считается. Пример: q = (1/2, 1/4, 1/4, 0) при F = 4 даёт H = 1.5 и d = 0.75; при счётах 20, 10, 10, 0 по всем прогонам (N = 40) H с поправкой 1.5 + 2/(80 ln 2), около 1.536 | формула степени по Díaz и др. (2002); число относится к этой атаке |
| Степень анонимности по апостериорному распределению | оценки пар калибруются на других прогонах той же конфигурации изотонической регрессией истины пары на оценку (равные оценки в одном блоке) с добавленными одной верной парой ниже всех оценок и одной неверной выше всех, поэтому в каждом блоке есть верная и неверная пара и калиброванная вероятность c строго между 0 и 1; оценка между обучающими берёт блок ближайшей обучающей не выше её, оценка ниже всех нижний блок. Для выходного потока отложенного прогона вероятность входа пропорциональна c/(1 - c): это апостериор при равных априорных вероятностях и оценках входов, независимых при известном отправителе. d это средняя по выходным потокам энтропия апостериора, делённая на log2 F; она верна, только если калибровка верна для отложенного прогона, и сама по себе не оценка ни сверху, ни снизу. Рядом приводится средняя -log2 вероятности верного отправителя (перекрёстная энтропия): при калибровке по другим прогонам она в среднем не меньше энтропии отправителя при оценках входов этого выходного потока, и без допущения о независимости, поэтому оценивает сверху анонимность против сильнейшего нарушителя, который судит по этим оценкам. Нарушитель, который учитывает, что каждый вход связан ровно с одним выходом, и смотрит на всю матрицу оценок, может знать больше; против него анонимность не выше, и перекрёстная энтропия ограничивает её тоже. Если перекрёстная энтропия ниже средней энтропии, апостериор слишком осторожен и d завышает анонимность: против такого нарушителя степень не больше перекрёстной энтропии, делённой на log2 F. Если выше, апостериор плохо откалиброван для отложенного прогона и d ненадёжна, а перекрёстная энтропия по-прежнему оценка сверху. Числа в плане по данным полной серии ([#23](https://github.com/jimichi-org/jimichi/issues/23)). Пример: калибровка c = 1/3, 1/2 и 2/3 у трёх входов даёт шансы 1/2, 1 и 2 и апостериор (1/7, 2/7, 4/7) | мера против нарушителя, который пользуется значениями оценок |
| Эффективный размер множества анонимности | 2^H, число равновероятных кандидатов с той же энтропией, от 1 до F; Serjantov и Danezis (2002) называют эффективным размером саму H в битах. По рангам 2^H для H без поправки и с поправкой, по апостериорному распределению 2 в степени средней энтропии. В примере по рангам 2√2, около 2.83 | наглядно на защите |

Обвязка считает в каждой строке отчёта ROC AUC, точность top-1, TPR при FPR 0.01, ранг истинного
отправителя (true_rank) и места верного входа (rank_counts). Сводка по чистым прогонам строки даёт
медиану ранга, точность при базовой ставке при F стенда и при π, заданной до серии (-base, по
умолчанию 1/1000), с TPR по оценкам всех прогонов вместе и числом неверных пар, степень анонимности
по рангам и эффективный размер, без поправки и с поправкой Миллера-Мэдоу, если чистых прогонов два
и больше (при одном эти поля null). Степень по апостериорному распределению есть в lab/metrics и
проверена тестами с ответами, посчитанными вручную; её числа в плане по данным полной серии
([#23](https://github.com/jimichi-org/jimichi/issues/23)).

### Скомпрометированные цепочки

| Метрика | Определение |
|---|---|
| Доля цепочек с подставными входом и выходом | доля цепочек, у которых и первый, и последний узел подставные, то есть принадлежат нарушителю, который тогда связывает два конца цепочки; цепочка из одного узла считается, когда этот узел подставной. Равновероятный выбор h разных узлов из N, k из которых подставные, даёт k(k-1)/(N(N-1)), а при h = 1 даёт k/N |
| Доля цепочек с подставным узлом | доля цепочек, в которых есть хотя бы один подставной узел; равновероятный выбор даёт 1 - C(N-k,h)/C(N,h) |
| Доля отказов | доля попыток построить цепочку, в которых вход отдал зеркало, от которого клиент отказывается: в нём нет больше min(-missing, N - h) узлов списка или нет проверенного комплекта самого входа; комплект, не прошедший проверку, считается отсутствующим |
| Доля попыток, сорвавшихся при установке | доля попыток, в которых клиент выбирает цепочку, которую узлы не устанавливают: честный узел продлевает цепочку только к узлу, проверенный дескриптор которого у него есть, поэтому цепочка, где честный узел стоит прямо перед узлом, не отдающим свой дескриптор, срывается. Две доли цепочек выше считаются по установленным цепочкам |
| Доля восстановленного маршрута | R, доля позиций маршрута, занимающего которых нарушитель называет верно. Позиции эха: клиент, затем узлы цепочки по порядку. У клиента -peer mailbox стенда известен всем и позицией не считается: сторона это клиент, вход и середина. Подставной узел, следующий протоколу, знает позицию перед собой (у входа это клиент), свою и следующую. Виды подставных узлов складываются, только если нарушитель связал их цепочки (связанная пара ниже); в связанном виде новое название заполняет неизвестную позицию, а конфликтующее название не заменяет уже названное, поэтому итог зависит от порядка сложения. R цепочки берётся по одной связанной компоненте её подставных видов и одному порядку сложения видов этой компоненты, тем, при которых верно названных позиций цепочки больше всего; несвязанные виды не складываются. Компоненту и порядок по истине выбирает обвязка, а не нарушитель, поэтому R это оценка сверху того, что нарушитель может заявить таким сложением. Порядок, который начинается с видов самой цепочки, сохраняет всё, что они знают, поэтому R цепочки не ниже R каждого её вида в отдельности, а если все её виды в одной компоненте, не ниже R её сложенных видов; если у каждой цепочки эха свой клиент, а процесс -peer держит свой вход, то при трёх хопах никакое сложение не называет верно больше позиций цепочки, чем знают её виды вместе, и когда все её виды в одной компоненте, R ровно такая. Позиция, которую нарушитель не называет или называет неверно, не считается. При трёх хопах R входа эха 3/4, середины 3/4, выхода 2/4; у стороны -peer R входа 1, середины 2/3, mailbox 1/3. Атака, при которой узел раздаёт соседям разные онион-ключи, сюда не входит (THREAT_MODEL) |
| Модель доли восстановленного маршрута | распределение числа известных позиций при равновероятном выборе цепочки из полных зеркал, когда виды подставных узлов цепочки сложены. Выход выбирается вместе с цепочкой (эхо) или закреплён на честном или подставном узле (mailbox клиента -peer). Считается по позициям цепочки, на каждой из которых узел подставной или честный, выбор без возвращения; даёт среднее и стандартное отклонение R, долю цепочек с подставным выходом и доли цепочек с подставными входом и выходом и с подставным узлом. Текущий setup раскрывает номер хопа и при h > 3 ([#78](https://github.com/jimichi-org/jimichi/issues/78)); модель предполагает связанные виды. Доказательство точности объединения при h = 3 автоматически на более длинные цепочки не переносится |
| Доля цепочек с раскрытым содержимым | доля цепочек, хотя бы одно сообщение которых нашлось байт в байт внутри чего-нибудь, что записали подставные узлы, среди цепочек, отправивших хотя бы одно сообщение; число остальных приводится. В сценариях наблюдения узлов (блок 3) целое сообщение состоит из 128 случайных байтов без номера потока, сообщения или другой метки, иначе поиск вхождения нашёл бы, например, сообщение из одних нулей в любой записи с нулями; сообщение из одинаковых байтов метрика не принимает. Единица это цепочка, а не сообщение: сообщения одной цепочки раскрываются вместе, и биномиальная ошибка по числу сообщений была бы занижена. Модель: доля цепочек с подставным выходом у эха (k/N при равновероятном выборе); у клиента -peer 0, потому что mailbox держит только записи сквозного слоя. По раскрытым цепочкам приводится ещё доля найденных сообщений; она близка к 1, сообщения, не дошедшие до выхода к концу прогона, не находятся |
| Оценка пары по запаздыванию | два сговорившихся узла записывают по одним часам одно событие каждой своей цепочки, установку или закрытие: a_i на первом узле и b_j на втором. Если одно из событий не записано, оценка неопределённая. Установка: 1/(1 + (b_j - a_i) в секундах), если b_j не раньше a_i; если раньше, пару исключает порядок событий (второй узел получает установку только после того, как первый продлил цепочку), и она получает оценку ниже неопределённой: исключённая пара наверняка ложная, а у неопределённой событие просто не записано. Закрытие идёт по цепочке в обе стороны, и выход может закрыть её раньше входа (простой, возраст, обрыв дальше по цепочке), поэтому порядок закрытия пару не исключает и оценка симметричная, 1/(1 + \|b_j - a_i\|). Оценка ограничена, поэтому никакая задержка не опускает допустимую пару ниже исключённой. ROC AUC и TPR при FPR 0.01 считаются по всем парам, точность top-1 по цепочкам первого узла, прошедшим и второй, как в связывании отправителя и получателя |
| Оценка пары по общему каналу | для соседних подставных узлов: 1, если исходящий канал одного и входящий канал другого это один канал (адрес и порт каждого конца совпадают накрест; адрес IPv4 в форме IPv6 равен самому IPv4), 0, если нет, неопределённая, если канал не записан. Канал несёт одну цепочку, поэтому, пока пара адресов канала не повторяется внутри прогона (сценарий блока 3 проверяет это в каждом прогоне, в плане), ROC AUC и top-1 здесь 1 по построению |
| Связанная пара | нарушитель связывает цепочку первого узла с цепочкой второго, если оценка этой пары выше 0 и единственная наибольшая и среди пар этой цепочки первого узла, и среди пар этой цепочки второго: цепочка проходит каждый узел один раз, поэтому связь взаимная. Если наибольшую оценку делят несколько пар (точное равенство), связи нет: выбор между равными не связывание. Цепочка первого узла, не прошедшая второй, может связаться с чужой; доля ложных связей среди сделанных приводится отдельно. По связанным парам складываются виды для доли восстановленного маршрута |
| Время до связывания | наименьшее окно наблюдения из сетки, заданной до серии, начиная с которого точность top-1 по цепочкам, прошедшим оба узла, равна 1 на нём и на каждом большем окне сетки; null, если на наибольшем окне она ниже 1. Одной ничьей достаточно, чтобы top-1 была меньше 1. Рядом приводится top-1 на каждом окне. Оценка по запаздыванию установки от окна не зависит: время 0, если её top-1 равна 1, иначе null. По прогонам приводится медиана, в которой прогоны без связывания стоят выше любого окна сетки (null, если на середину приходится такой прогон), и число таких прогонов |
| Склейка разговоров у mailbox | mailbox склеивает две цепочки, если одна кладёт в очередь, из которой забирает другая; одного направления достаточно. Доля это число разговоров, хотя бы две цепочки которых склеены, делённое на число разговоров прогона; пары цепочек разных разговоров считаются отдельно как ложные |
| Признак заявки у mailbox | ROC AUC признака заявки, например «в заявке есть put», против истины «запись заявки несёт сообщение», по заявкам, отправленным, пока сессия отправителя установлена и не устарела: до установления сессии put несёт только запись рукопожатия, пока mailbox её не сохранил, а при устаревшей сессии новые записи не запечатываются, поэтому там put следует за рукопожатием, а не за сообщениями и фоном, даже с -cover-puts. Сообщение всегда идёт с put, поэтому AUC признака put равна 0.5 + q/2, где q это доля заявок без сообщения, у которых нет и put. С -cover-puts put нет только на тиках, где заполнено окно put, и AUC ровно 0.5, только если таких тиков не было; число заявок без put приводится, а совпадение с угадыванием заявляется только эквивалентностью. Заявки двух цепочек одного разговора и пересобранной цепочки зависимы, поэтому бутстрэп идёт по разговорам и даёт интервал внутри прогона; единица сравнения прогон |
| Стандартная ошибка доли | sqrt(p(1-p)/n) для доли из n независимых попыток при значении p, которое даёт модель; n это число установленных цепочек, а для долей отказов и срывов число попыток; для средней доли восстановленного маршрута по n цепочкам (у клиентов -peer по n процессам) это σ/sqrt(n), где σ это стандартное отклонение R по модели: R принимает несколько значений, и биномиальная формула к ней не применяется |

### Неразличимость трафика

Статус: реализовано, чисел нет. Различитель отличает ячейки с сообщением от фоновых на канале
клиент-вход по моментам ячеек потока и ответов на них (нарушитель П2); набор `cmd/lab -set cover`,
разметка ячеек, признаки и отчёт описаны в блоке 7. Различитель потоков в плане.

| Метрика | Определение |
|---|---|
| AUC различителя ячеек | линейный дискриминант по признакам ячейки: w = S_t^-1 (μ1 - μ0), где μ1 и μ0 средние признаков ячеек с сообщением и фоновых, а S_t сумма (x - μ)(x - μ)^T по всем обучающим ячейкам, μ их среднее. Для двух классов S_t = S_w + (n1 n0 / n)(μ1 - μ0)(μ1 - μ0)^T, где S_w внутриклассовый разброс, поэтому, когда S_w обратима, w направлен как дискриминант Фишера S_w^-1 (μ1 - μ0); это же направление наименьших квадратов для метки класса (Hastie, Tibshirani, Friedman, 2009). Если сочетание признаков постоянно внутри каждого обучающего класса и различается между классами, S_w вырождена, а w идёт по этому сочетанию: отбросить его значило бы скрыть самую сильную утечку. Признак, постоянный на обучающих ячейках или линейно выраженный через признаки до него (1 - R^2 не больше 1e-9), не используется; это правило теряет и сочетание с разбросом меньше примерно 1e-4 стандартного отклонения признаков, поэтому набор признаков строится без точных линейных связей, а неиспользованные признаки печатаются. Оценка ячейки w·(x - (μ1 + μ0)/2) / (w·(μ1 - μ0)): средние классов на обучении получают +1/2 и -1/2, поэтому, пока правило выше не отбрасывает признак, оценки не зависят от единиц признаков, а у всех прогонов серии одна шкала. AUC против истины «ячейка несёт сообщение», интервал внутри прогона бутстрэпом по потокам. Обучение идёт на ячейках отдельных обучающих прогонов той же конфигурации, которые идут до серии со своими зёрнами из отдельного потока и в неё не входят; каждый прогон серии проверочный. Направление задано до серии и одно для всех её прогонов, поэтому AUC прогонов серии независимы при этом направлении, AUC ниже 0.5 не заменяется на 1 - AUC и при неразличимости в среднем равна 0.5, без сдвига вверх. Не определена (NaN, в отчёте null), если в проверочном прогоне нет ячеек одного из классов (в немедленном режиме без -cover фоновых ячеек нет); если обучение не даёт направления (нет ячеек одного из классов, не осталось признаков или средние классов совпали по каждому оставшемуся признаку), AUC не определена у всей конфигурации. Такой прогон в медианы не входит и считается в сводке отдельно, с причиной; конфигурация без направления не даёт заявления неразличимости по AUC, а D и TV у неё приводятся как обычно. Пример: обучение (2, 0), (4, 0) с сообщением против (0, 1), (0, 3) даёт S_t = [[11, -6], [-6, 6]] и w = (1/5, -2/15), то есть 2/15 от w Фишера (3/2, -1); проверка (3, 1), (1, 1) против (1, 0), (0, 2) получает оценки 9/26 и -3/26 против 1/26 и -1/2 и верно упорядочивает 3 пары из 4, AUC 0.75 |
| AUC по признаку | тот же различитель на одном признаке: направление по знаку разности средних классов на обучающих прогонах, AUC на прогоне серии без отражения; не определена, если признак постоянен на обучении или средние классов равны. Показывает, какой признак разделяет классы |
| Расстояние Колмогорова-Смирнова | D = max по x \|F_a(x) - F_b(x)\| между эмпирическими функциями распределения признака у ячеек с сообщением (a) и у фоновых (b) одного прогона; равные значения по правилу раздела «Сравнения» дают одну ступень. Если D и AUC считают значения равными по одному правилу, для самого признака как оценки на той же выборке \|AUC - 0.5\| <= D. p внутри прогона не приводится: значения одного потока зависимы, а асимптотическая формула и при независимых значениях на этих размерах не точна (8 и 8 значений, D = 1/2: 0.188 против точного 1819/6435, около 0.283). Рядом нулевой уровень: D того же прогона после случайного кругового сдвига последовательности меток каждого потока, одна выборка сдвига на прогон. Сдвиг сохраняет размеры групп, от которых D зависит, и сгущение сообщений во времени и рвёт только связь меток с признаками; нулевой уровень верен, если без утечки метки не зависят от признаков, а процессы внутри прогона стационарны. Случайная перестановка меток ячеек сохраняет размеры, но не сгущение: при сгущённых метках и медленно меняющихся признаках её D занижен. Прогоны сравниваются по D и нулевому уровню, раздел «Сравнения». Пример: a = {1, 2, 3, 4} и b = {3, 4, 5, 6} дают D = 1/2 |
| Полная вариация по корзинам | TV = 1/2 сумма \|p_k - q_k\| по k для B = 16 корзин равной частоты объединённой выборки из N значений обеих групп: группа равных значений, наименьшее место которой по возрастанию r (от 0), идёт целиком в корзину floor(B r / N); корзины строятся без меток. (1 + TV)/2 это точность лучшего правила, которое судит о группе по корзине одного значения при равных долях групп. Корзины огрубляют распределения (у чередующихся выборок 1, 3, ..., 31 и 2, 4, ..., 32 TV по 16 корзинам равна 0, хотя общих значений нет), а при малых группах выборочная TV завышена и для одного распределения, поэтому она не оценка сверху и не оценка снизу; рядом нулевой уровень, как у D. Пример с тремя корзинами: a = {1, 3} и b = {2, 4, 5, 6} дают p = (1/2, 1/2, 0), q = (1/4, 1/4, 1/2), TV = 1/2 |
| Точность при базовой ставке | как в связывании, по оценкам различителя ячеек всех прогонов серии вместе: направление у них одно, поэтому общий порог имеет смысл; π это доля ячеек с сообщением в сети, о которой делается вывод; сводка блока 7 приводит её при доле ячеек с сообщением в чистых прогонах серии с определённой AUC, с числом фоновых ячеек, на котором стоит FPR |
| Различитель потоков (в плане) | D и TV межпакетных интервалов потоков, которые несут сообщения, против потоков, которые шлют только фоновые ячейки; нулевой уровень: те же расстояния после случайного разбиения всех потоков прогона на группы тех же размеров. Нужен режим стенда, в котором часть клиентов не отправляет сообщений |

### Блок 2. Активный нарушитель П3, временная метка в потоке

| Слот h; символ | 200 мс; четыре слота |
| Закрытый слот +1 / -1 | слот 0 / слот 2; остальные слоты не добавляют намеренного ожидания |
| Эпоха / конец метки | Origin + 2 с / Origin + 11.6 с |
| Сдвиги / конец последнего интервала поиска | 0, 25, ..., 600 мс / Origin + 12.0 с |
| Проба / граница захвата | Origin + 12.2 с, через 200 мс после последнего интервала / Origin + 16 с |
| Периоды узлов; отношение к 50 мс | выключено, 25, 47.5, 50, 52.5, 75 мс; выключено, 0.5, 0.95, 1, 1.05, 1.5 |
| Немедленный клиент | экспоненциальные интервалы сообщений со средним 200 мс и добавочный фон раз в 66 666 667 нс; период клиента null |
| ConstantRate | период 50 мс, без добавочного фона |
| Нагрузка / набор / повторы | сообщение 128 байт; основной c25519, ГОСТ поддерживается; сорок блоков повторов |

Каждый блок выполняет все 24 сочетания двух режимов клиента, шести периодов узлов и активного
воздействия/фиктивного контроля в случайном порядке, с новыми ключами и ресурсами. Соответствующие
условия имеют общие случайные интервалы нагрузки, код и цель. Независимые домены зёрен дают
нагрузку/фазы, код, цель, перестановку кандидатов и порядок условий. Одинаковые зёрна нагрузки
не воспроизводят шифрование, фазы узлов и планирование ОС. Оба режима предлагают приблизительно
двадцать кадров/с; совпадают номинальные средние, а не фактические расписания и распределения.
Фиктивный контроль использует ту же обёртку кадров без обращения к символам кода.
Пять одновременных кандидатов не задерживаются намеренно.

Все шесть исходных цепочек должны установить наблюдаемые последние каналы и передать кадры
установки. Коллекторы ответов с обязательным ожиданием завершения требуют отдельное предварительное
эхо от каждой цепочки за пять секунд; заблокированные отправки прерываются закрытием собственных
соединений. Origin следует за всеми наблюдениями готовности. Сбои установки остаются попытками.
Шестнадцатисекундный горизонт сохраняется после закрытия всех цепочек. Каждая отдельная проба
вызывается независимо от заблокированного обычного Send. Граница захвата предшествует служебному
закрытию и ожиданию работников; поздние ответы и служебные закрытия исключаются. Переподключений
нет. Переполнение очередей и закрытие считаются исходами доступности.

Для кандидата j, символа k и сдвига l считаются A в `[epoch+4kh+l, epoch+(4k+1)h+l)` и B в
`[epoch+(4k+2)h+l, epoch+(4k+3)h+l)`. d=(B-A)/(A+B), либо ноль для двух пустых интервалов.
Оценка равна `Round(1e9 * sum(code[k]*d[k])/12)`, при выводе делится на 1e9. Берётся максимум
по всем кандидатам и сдвигам. Для всех 924 сбалансированных кодов повторяется полный поиск;
число максимумов не меньше наблюдаемого, делённое на 924, даёт p. Решение принимается только
при p<=0.05, положительном максимуме и единственном лучшем кандидате. Равные кандидаты дают
ambiguous; среди равных сдвигов показывается наименьший. Пустые пары остаются в знаменателе
и не дают положительного свидетельства. Детектор получает только переставленные временные
метки последнего канала, код, границы часов и параметры поиска. Истина, закрытия, счётчики
воздействия и входные трассы в детектор не поступают.

При глобальной нулевой гипотезе отсутствия метки случайное назначение кода должно быть независимо
от наблюдаемой трассы. Полный перебор консервативен для этой гипотезы, минимальное p=1/924.
Он не ограничивает ошибочную атрибуцию при настоящей метке: общий хост влияет на ложных кандидатов,
а само закрытие может вносить временной признак. Обучаемого порога и перестановок кадров/окон нет.
Ручной тест задаёт у цели d, равное коду, оценку 1, пять кандидатов с нулевой оценкой, один
крайний код из 924, p=1/924 и AUC 1. Это тестовые данные, а не измеренный результат стенда.

| Величина | Знаменатель и смысл |
|---|---|
| Верное, ошибочное, ambiguous, none | верное решение на выполненную плановую попытку и на установленную оцениваемую попытку; сбои отдельно |
| Решения фиктивного контроля | любое решение на оцениваемую фиктивную попытку |
| Реализация метки | завершённые задержанные кадры по символам, начатые/прерванные ожидания, плановое и прошедшее время; none, partial или complete |
| Открытая цепочка | нет наблюдаемого клиентом закрытия до границы; установленные попытки с известным состоянием, покрытие и границы неизвестных |
| Отзывчивая цепочка | открыта на границе и отдельная проба получила эхо до неё; одного nil от Send недостаточно |
| Совместная идентификация/живучесть | верное решение с открытой либо отзывчивой цепочкой на выполненную плановую попытку |
| Все цепочки | доля открытых в каждом прогоне; шесть цепочек не являются шестью независимыми блоками |
| AUC | цель против пяти ложных кандидатов по максимумам сдвигов в каждом установленном оцениваемом активном прогоне; закрытые и пустые сохранены |
| Задержка доставки | от вызова до совпавшего эха, p50/p95/p99 условно по ответам до границы; число образцов и неотвеченных |
| Доставка и цена | начатые вызовы, nil/ошибки, незавершённые, эхо, nil без эха и отброшенные клиентом; предварительные и отдельные пробы отдельно |
| Множитель кадров | завершённые кадры вперёд/назад на входном/последнем канале в [Origin, граница), делённые на успешные возвраты Send до границы; при нуле null |

Возврат nil от Send не доказывает принятие в очередь. Снимки счётчиков имеют фактическое время
после ожидания работников. Разности задержки активного/фиктивного режима сохраняют только пары
с определёнными значениями и показывают покрытие. Интервалы Уилсона 95% используют одно бинарное
наблюдение цели на конфигурацию и блок повторов. AUC приводится распределением значений прогонов,
без объединения кандидатов и подмены правила решения. Отсутствующая телеметрия даёт unscorable
или unknown; достоверная тишина остаётся данными.
Учёт доставки, задержки и кадров независим от пригодности данных для детектора. Доступные значения
сохраняются при неполном захвате и отказе детектора, со статусом partial и покрытием наблюдаемых
потоков/трасс. Отсутствующие числа равны null; наблюдённый ноль остаётся нулём. Загрузка хоста
записывается до и после каждой попытки, включая сбои, со статусом available/unavailable и null
при недоступности. Это контекст для оценки влияния общего хоста, а не порог исключения.

Единственная проверяемая статистически величина: доказанное верное решение с отзывчивой цепочкой
на выполненную плановую попытку. Каждый положительный период узла сравнивается с нулём внутри
режима клиента по парным блокам, критерием Уилкоксона. Холм имеет фиксированное семейство десяти
сравнений; вырожденное p=1, недоступные позиции занимают 1 при поправке и затем становятся null.
Неполные серии и сокращённые повторы описательные. Межрежимные различия и разности цены
активного/фиктивного режима описательные. Незначимость не доказывает эквивалентность или порог стойкости.

```sh
go run ./cmd/lab -set mark -repeats 40 -suite c25519 -seed 1 -rev <verified-commit> -out artifacts
go run ./cmd/lab -set mark -mark-replay artifacts/mark-v1-<run>/observations.jsonl
```

Отдельный каталог `mark-v1` содержит манифест с матрицей/ревизией/средой/зёрнами/порядком,
пополняемый журнал попыток, вход детектора без истины, отдельный JSONL истины/оценки и сводку
с числами, знаменателями, покрытием и сравнениями. Повтор только по наблюдениям точно вычисляет
оценки, p и решение. Время хранится целыми наносекундами общих часов трассы; отсутствующее
значение null со статусом. Ключи, сообщения, адреса и идентификаторы цепочек не сохраняются.
Вместо сырых ошибок записываются нормализованные классы. Неудачные, закрытые, неоцениваемые
и не давшие эффекта попытки сохраняются; фатальная ошибка вывода/среды/очистки оставляет неполный
манифест. Серия содержит 960 прогонов и 4 ч 16 мин захвата, плюс установка, очистка и анализ.

Границы: один процесс на loopback, прикладное время завершения кадра, известная эпоха/общие часы,
шесть кандидатов, один масштаб метки и ограниченный поиск сдвига. Эксперимент не устанавливает
стойкость к произвольным активным атакам. Сорок повторов дают ограниченную точность редких решений.

#### Наблюдение настоящих узлов

Пять узлов и каждый клиент или сторона разговора работают в отдельных добровольно запущенных
процессах на собственном loopback-стенде. Наблюдаются один или два выбранных узла, включая
все роли и отсутствие выбранного узла в цепочке. Каналы аутентифицированы; комплекты проверяют
производственные `verify.Peer`, `MirrorEntries` и функции выбора клиента. Каждый процесс
сам создаёт ключи и держит их у себя. Linux/amd64, `HardenProcess` и действующий `mlock`
обязательны. Разные процессы одного пользователя не образуют песочницу против этого пользователя.

| Граница | Наблюдение и проверка |
|---|---|
| Установка и слой | успешное открытие собственного setup, фактический hop index, предшественник, собственная позиция и следующий узел; сосед подтверждён только после аутентификации канала |
| Ячейка и кадр | точное равенство реально переданных буферов и поколения AEAD/соединения связывают входящий кадр, собственный слой и исходящую запись; неоднозначность делает наблюдение недоступным |
| Счётчики | в RAM проверяются область меньше 2^62, направление и index, переходы +1 по модулю 2^62, постоянный сдвиг между точно сопоставленными входом и выходом; публикуются числа образцов, проверок, нарушений и пропусков |
| Жизненный цикл | открытый setup, созданный шифр хопа, локальная обработка, Seal транспорта и полная запись различаются; обработанная ячейка может остаться в pacer и исчезнуть при обычном закрытии |
| Содержимое | приватная оценка ищет целиком уникальные случайные сообщения по 128 байт в реально наблюдённых фрагментах своего слоя и Deliver; номера потока, сообщения и метки в payload не кодируются |

Фоновый запрос выхода без Deliver, настоящий Deliver с пустым ответом и настоящий ответ
различаются. Все они остаются KindData; KindPadding учитывается только на транспортном уровне.
Сырые circuit ID, nonce, counter, смещения, адреса, F, сообщения, записи и события не сохраняются.
Агрегаты `relay.Stats` дополняют проверки счётчиков и не заменяют их. Ненаблюдение сообщения
в этих фрагментах не доказывает его отсутствия во всей памяти процесса.

Предсказание получает только виды выбранных узлов и объявленные параметры. Приватные маршруты,
пары сторон, сообщения, реальные/фиктивные метки, реализованное расписание и зерно ему недоступны.
Истина присоединяется после фиксации оценок и связей. R по связанным компонентам остаётся
оценкой сверху с выбором компоненты и порядка по приватной истине, а не знанием нарушителя.

Время берётся в callback по `CLOCK_MONOTONIC` одного ядра. Для данных и кадров окно полуоткрыто,
для освобождения шифра хопа включает границу cutoff. Ограниченный дренаж после cutoff только
заканчивает доказательство происхождения уже измеренных событий. Поздняя запись или очистка
не улучшает AUC, время связывания и экспозицию. Неравные сроки жизни, обычное закрытие, ошибка
записи, отсутствие будущей записи и цензурирование сохраняются раздельно.

В полном прогоне `Unanswered` считает отправленные сообщения приложения без наблюдённого
получения, сопоставленного по сообщению целиком в приватной истине. Для эха это совпавшее эхо,
для peer - получение приложением собеседника. Неотправленные и только полученные записи исключены.

#### Доверие и зарегистрированные сценарии

Доверенный вариант моделирует одну или две заранее объявленные позиции ростера, которыми
владеет нарушитель с сертификатами УЦ стенда. Он не моделирует кражу УЦ, Sybil-приём или
допуск любой личности того же УЦ: валидная личность вне ростера получает отдельный отказ.
Узлы второго УЦ имеют валидные сертификаты под своим якорем. Проверяются эхо, честный
закреплённый mailbox и mailbox второго УЦ, k = 1/2 и -missing = 0/1/2; учитываются отказы,
исключение из соседей и отсутствие соединений к отвергнутому узлу. Прежний тест эха ниже
остаётся отдельным свидетельством.

| Набор | Заданный план, не результаты |
|---|---|
| compromise | N = 5, h = 3; эхо k = 1/2, честный и подконтрольный mailbox k = 1/2; полные конечные проверки всех 60 маршрутов эха и 12 маршрутов к закреплённому выходу на обоих наборах примитивов |
| collude | F = 5/10/20; немедленный клиент/Period 0, фиксированные 35 мс/Period 0 и фиксированные 35 мс/Period 33,25 мс; 20 с, корзины 100 мс, окна 1/2/5/10/20 с |
| Контроли collude | последовательная установка, обе соседние пары, неполные партнёры с лишними кандидатами; частные сроки жизни 10..20 с, часть цепочек открыта на cutoff |
| mailbox | восемь разговоров, cover puts выкл./вкл. и Period 0/33,25 мс; 30 с: активность 0..10 и 20..30 с, тишина 10..20 с с продолжающимся опросом; средний интервал сообщений 200 мс |
| Контроли mailbox | mailbox вместе со входом или серединой; настоящее заполнение окна и очереди, sticky-копии, молчащая сторона, нет сообщений, до сессии, stale и пересборка; неизвестная метка проверяется отдельным тестом отказа |

Для mailbox явно заданы Rate 35 мс, Window 16, ReplyTimeout 7 с и Keepalive 1 с.
Конструктор с обычным ReplyTimeout 10 с такой Rate отвергает; defaults не меняются.
Контроли `mail-P0-defaults` и `mail-P33250000-defaults` сохраняют 30 с наблюдения,
Keepalive 30 с и cover puts off. На сторону заранее заданы ровно 100 попыток: по 50
в каждом активном отрезке, в моменты 0.1 + 0.2j и 20.1 + 0.2j с, j = 0..49.
В тишине 10..20 с новых сообщений нет, опрос продолжается.
Отсутствие фиктивных записей даёт `missing_class`, их фактическое появление
тоже сохраняется без переметки. Эти описательные контроли не входят в обучение, пилот
и основную серию и не заменяют обязательный различитель при cover puts off.
Экспоненциальная нагрузка основной матрицы не меняется.

До обычного наблюдения mailbox обе стороны независимо сообщают об аутентифицированной
готовности сессии: инициатор в Established, ответчик в Confirmed, роли определяются порядком
открытых ключей. Общий конечный барьер предшествует эпохе наблюдения; он подтверждает прошлую
готовность, а не одновременный снимок сессий. В контроле пересборки дочерний процесс доказывает
закрытие исходной цепочки, новое завершённое построение и подключение пересобранной цепочки.
После слияния и разрешения истины контроллер отдельно требует для каждого заданного источника
совпадающую строку только приёма у противоположной стороны. Доставка ограничена жизненным
циклом захвата и дренирования; у строк сообщений нет метки времени доставки.

До создания участников стохастическое расписание источника проверяется по необходимому
условию вместимости. При накоплении наблюдений проверяются фактическая защищённая память,
ёмкости скалярных массивов и полный внутренний поток измерений в байтах и кадрах.
Превышение границ делает захват неполным и блокирует зависимые этапы. Исходное расписание
не обрезается, отказавшие и незапущенные позиции сохраняются без замены.

Все loopback-узлы явно отключают только четыре ограничения на один исходный IP:
MaxHandshakesPerSource, MaxLinksPerSource, SourceLinkRate и SourceSetupRate равны -1.
Общие пределы MaxHandshakes 32 и MaxLinks 512 сохраняются; начальные рукопожатия клиентов
идут не более чем по 16 одновременно. Это поправка стенда на общий IP, не новые defaults.
Источник комплектов проверяется без HTTP, gossip и ротации, их покрывают отдельные проверки.

Связывание использует setup, фактическое освобождение шифра хопа, ячейки на входящем канале
и общий канал соседей. Контроль П1 считает все сырые кадры на тех же каналах того же захвата,
включая padding; он не воспроизводит опубликованную топологию блока 1. Приводятся AUC, top-1,
TPR, ложные связи, отсутствие партнёра и цензурированное время связывания. Точная ничья
не создаёт связь; постоянный ряд даёт неопределённую корреляцию, а не измеренный ноль.

Время связывания означает начало подтверждённого совершенного суффикса сетки
1/2/5/10/20 с. Проверенное связывание по setup даёт 0 независимо от последующих окон.
Неполученный вид не доказывает отсутствие связи:

| Состояние времени | seconds | censored |
|---|---|---|
| Подтверждённое связывание | 0, 1, 2, 5, 10 или 20 | false |
| Полученное наблюдение без устойчивой связи | null, причина censored | true |
| Наблюдение недоступно | null, отдельная причина | false |

Сводка сохраняет Runs = Defined + Censored + Missing; Failed пересекается с этими группами.
Медиана времени условна по полученным наблюдениям Defined + Censored. Недоступные окна
сохраняются в Missing, но не получают вымышленную точку cutoff. Для AUC сохраняются все
доступные конечные значения, включая помеченные неудачей прогоны; причины и знаменатели
показываются отдельно. Это не заменяет требования полноты основной серии.

#### Различители mailbox и выпуск отчёта

Отдельно обучаются два направления LDA: заявки (настоящая запись против остальных допустимых
заявок) и только put с записью данных (настоящая против фиктивной). Фактическая метка берётся
при Seal сквозной записи и связывается с точными байтами отправленного record; sticky-копии
сохраняют метку оригинала. Неизвестная запись не становится отрицательным примером. Разделение
обучения и оценки проходит по целым разговорам вместе со всеми копиями. Признак has_put
приводится отдельно: q это доля отрицательных заявок без put, AUC_put = 0.5 + q/2.

Связывание очередей строит кандидатов по полным наблюдаемым put/fetch в измеренном окне,
включая handshake, pre-session и stale. Приватная допустимость заявки ограничивает put/LDA,
но не скрывает публичное равенство очередей. Истинные пары применяются после построения
кандидатов для подсчёта правильных, ложных и отсутствующих связей.

Вход `mailbox18-release-v2` сохраняет 18 признаков: наличие put, вид и номер записи, модульный
шаг номера, наличие предыдущей записи, повтор record, интервалы и признаки наличия предыдущей
заявки/put, остаток интервала от периода, четыре исхода предыдущего put, время и наличие
предыдущего забора этой очереди другой цепочкой, длительность Deliver. До обучения и оценки
применяется одно фиксированное огрубление:

| Признак | Кодирование |
|---|---|
| Номер и модульный шаг uint32 | floor(x/256), насыщение 4095 |
| Интервал заявки или put | корзины 5 мс, насыщение 4095 |
| Остаток интервала от ближайшего кратного периода | floor(ns/1000000), включая отрицательные; ничья кратных в меньшую сторону |
| Время после чужого забора очереди | ограничение 30 с, корзины 10 мс |
| Длительность Deliver | корзины 10 мкс, насыщение 4095 |
| Категории и признаки наличия | без изменения; отсутствие времени отличает отдельный признак наличия |

Сырые строки, времена, counters и модели по неогрублённым признакам не выпускаются даже как
хэш. Модель и целочисленные моменты/экстремумы кодированных признаков выпускаются только после
полного чистого обучения: не меньше 64 строк каждого класса из не меньше четырёх разговоров,
ни один разговор не даёт больше половины класса, метки проверены независимо, направление
конечно и ненулевое, арифметика проверена в RAM. Иначе остаются числа поддержки и причина,
без коэффициентов, моментов и digest; такая модель не допускает основную серию.
Агрегаты, ранги и огрублённая модель раскрывают статистику и могут раскрыть кодированные
категории при дополнительных сведениях; невозможность вывода исходных данных не заявляется.
Чувствительность выбора столбцов или pivot к погрешности запрещает выпуск модели. Моменты
позволяют проверить арифметику, но не подтверждают происхождение событий, исходный порядок
строк или точные сырые наблюдения; для этого нужны отдельные проверки исходников и RAM.
Вывод кодированных строк этим не исключён. Групповой bootstrap AUC использует 2000 выборок,
анонимный порядок групп фиксируется до расчёта и одинаков в отчёте и свидетельстве аудита.

`Manifest.Resources` сохраняет один максимум RSS в целых байтах для всей фазы: максимум
индивидуальных пиков всех созданных участников, включая pooled trainer и fit-auditor,
и контроллера до завершения расчёта плана. Scope равен
`owned-process-peaks-through-finalization-v1`. Пики процессов не суммируются; это не
одновременное потребление стенда. Последующая сериализация не входит в измеренную точку.
Неполученный Wait или usage оставляет null с причиной. Поле `max_rss` отдельных traffic-прогонов
сохраняет прежнюю область; один pooled-пик не копируется в пять независимых строк.

Фазы `structural`, `train`, `pilot`, `primary` и план фиксируют исходники, дерево, оптимизированный
бинарник, конфигурации, модели и зерна до основной серии. Зарегистрированы 13 нетривиальных
заявлений модели и 13 парных сравнений: девять node-cell/raw-frame и четыре cover-on/off
для двух периодов и двух различителей. Допуск 0.05, семейство 0.05, мощность 0.8 не меняются.
Для модели исходный минимум 2048 попыток на нетривиальную строку увеличивается по расчёту
объёма и точной мощности Уилсона; для разностей нужны пять отдельных пилотов и не меньше
30 основных прогонов на точку. Пять обучающих прогонов mailbox не входят в пилот и серию.
Объём разностей выбирается точным Уилкоксоном по всем n = 30..512 с 10000 симуляций на n;
нормальная аппроксимация не допускается. ГОСТ выполняет отдельные описательные проверки,
без переноса направления обучения и без вывода эквивалентности между наборами.

Для `train`, `pilot` и `primary` требуется сохранённый sealed-план текущих исходников и бинарника.
Обучение принимает только Structural predecessor, последующие планы содержат его digest
в цепочке ParentDigest. Базовое зерно основной серии связывается с заранее сохранённым
MainSeedCommitment; при запуске проверяется точное совпадение. Это учёт происхождения,
а не защита от оператора, переписывающего собственные файлы. Все структурные проверки
и обязательные наблюдения остаются отдельными условиями готовности.

Точный критерий предполагает обменяемость знаков парных разностей, обычно симметрию вокруг
нулевого сдвига; он не проверяет равенство средних при произвольной асимметрии. Незначимость
не устанавливает угадывание или «не хуже П1».

Все плановые попытки, отказы, срывы, недоступные виды, неполные классы и ошибки захвата остаются
в учёте и масках; у каждой метрики указан её допустимый знаменатель. Ноль отличается от null.
Дополнительные попытки не заменяют неуспехи ради нужного числа успехов.
Неполный пилот, недостаточная поддержка, неразрешённая мощность или
стоимость останавливают переход к основной серии. Неблагоприятная AUC может быть честным
результатом; пропущенный обязательный сценарий завершением блока не считается.

#### Ранее реализованная выборка и модель

Выбор цепочки измеряется без трафика и без узлов. `cmd/lab -set paths` делает -samples попыток
выбрать цепочку из -hops узлов среди -nodes так же, как клиент, его собственными функциями
выбора входа, приёма зеркала или отказа от него и выбора остальной цепочки, на потоке,
выведенном из -seed, вместо системного генератора: вход среди всех узлов, отказ, когда в его
зеркале нет больше min(-missing, N - h) из них (это граница) или нет проверенного комплекта
самого входа, остальные хопы среди узлов,
которые есть в зеркале. Выбранная цепочка затем устанавливается, когда каждый её узел продлевает
цепочку к следующему, и здесь обвязка применяет правило узла: честный узел продлевает только к
узлу, дескриптор которого у него есть, подставной к любому. Подставными считаются первые -rogue
узлов, и действуют они сообща:

| Флаг | Что делают подставные узлы | Что это меняет в цепочках |
|---|---|---|
| -leftout o | каждый из них как вход исключает из своего зеркала o честных узлов | выход при подставном входе выбирается из N - o - 1 узлов, k - 1 из которых подставные |
| -withhold w | w из них не отдают свои дескрипторы честным узлам | в зеркале честного входа нет w узлов: в пределах границы его цепочка выбирается среди N - w узлов, которые в зеркале есть, сверх неё попытка получает отказ. Ни один честный узел не продлевает цепочку к узлу, не отдающему дескриптор, поэтому цепочка, выбранная через подставной вход, срывается при установке, когда честный узел стоит прямо перед таким узлом |

Когда оба равны 0, как по умолчанию, все зеркала полные, все цепочки устанавливаются и выбор
равновероятный. Попытка кончается одним из трёх исходов: отказ, срыв цепочки при установке,
установленная цепочка. Отчёт даёт доли отказов и срывов и, по установленным цепочкам, обе доли
цепочек, каждую рядом со значением, которое даёт модель, и стандартной ошибкой доли при этом
значении, а рядом значения равновероятного выбора. Конфигурация, в которой ни одна попытка не
даёт установленной цепочки, не принимается: цепочек, по которым считать долю, нет. В строке
отчёта записаны nodes, hops, rogue_nodes, missing, left_out, withheld, samples, seed и rev,
поэтому ту же выборку можно получить снова. Файл отчёта назван по всем этим значениям, кроме
rev, и по секунде записи, поэтому два прогона в пределах одной секунды затирают друг друга,
только когда не отличаются ничем, кроме rev.

Строки, полученные при одном зерне, читают один и тот же поток: пока ни одна попытка не
получает отказ, входы в них одни и те же, а честный вход с полным зеркалом выбирает одну и ту
же цепочку. Такие строки не являются независимыми выборками, и их доли могут совпасть до
последнего знака: при -leftout в пределах границы и без -withhold доля цепочек с подставным
узлом по выборке та же, что при полных зеркалах и том же зерне. Строки, которые нужны как
независимые выборки, берутся при разных зёрнах.

Значения, которые даёт модель, считаются точно, цепочки подставного входа суммированием по
виду узла на каждой позиции, и проверены в тестах метрики перебором по одной всех цепочек,
которые клиент может выбрать. Доля по выборке отличается от своего значения примерно на
стандартную ошибку. Там, где значение равно 0 или 1, доля точна по построению: каждая попытка
даёт один и тот же ответ, доля по выборке равна значению при любом зерне и любом числе попыток,
стандартная ошибка равна 0, и о выборе такая строка ничего не говорит. Частые случаи:

| Строка | Точная доля |
|---|---|
| подставных узлов нет или подставные все | обе доли цепочек, 0 или 1 |
| один подставной узел, цепочки из двух узлов и больше | подставные вход и выход, 0 |
| два подставных узла, оба не отдают дескрипторы, цепочки из трёх узлов и больше | подставные вход и выход, 0: перед выходом стоит честный узел, и он к нему не продлевает |
| честных узлов меньше, чем хопов | подставной узел, 1 |
| зеркала честных входов получают отказ (-withhold выше границы) | подставной узел, 1 |
| зеркала подставных входов получают отказ (-leftout выше границы) | подставные вход и выход, 0 |
| ни в одном зеркале не пропущено больше границы | отказы, 0 |
| ни один узел не скрывает дескриптор, или цепочки из одного или двух узлов | срывы при установке, 0 |

Печатная строка даёт четыре знака после запятой. Значение, которое они округлили бы до 0 или 1,
печатается с двумя значащими цифрами его расстояния до этого края, поэтому напечатанные 0.0000 и
1.0000 это ровно 0 и 1. Выборочная доля тоже может оказаться ровно 0 или 1: точна по построению
только та доля, у которой и скобка читается 0.0000 или 1.0000 +- 0.0000.

При N = 5, k = 2 и h = 3 упорядоченных цепочек 5 * 4 * 3 = 60. У шести подставные узлы на обоих
концах (2 варианта входа, второй подставной узел как выход, любой из 3 честных узлов между
ними): 6/60 = 0,1 = k(k-1)/(N(N-1)). В шести нет подставного узла (три честных узла в любом
порядке), значит в 54/60 = 0,9 = 1 - C(3,3)/C(5,3) он есть. Тест метрики перебирает все 60
цепочек и требует ровно эти значения.

При -leftout 1 в той же конфигурации подставной вход отдаёт четыре узла и выбирает два
следующих хопа из трёх остальных: 3 * 2 = 6 цепочек, две из которых кончаются вторым подставным
узлом. Честный вход отдаёт все пять: 4 * 3 = 12 цепочек, в десяти из них есть подставной узел.
Входом с вероятностью 1/5 становится любой узел, поэтому оба конца подставные с вероятностью
2/5 * 2/6 = 2/15 против 0,1 при полных зеркалах, а подставной узел есть в
2/5 + 3/5 * 10/12 = 0,9 цепочек, как и прежде. Свой дескриптор здесь никто не скрывает, поэтому
все цепочки устанавливаются.

При -withhold 2 и -missing 1 в зеркалах трёх честных узлов нет двух узлов, и они получают
отказ, 3/5 попыток. Каждая цепочка, которую выбирает клиент, входит через подставной узел,
который отдаёт все пять: 12 цепочек. В трёх из них честный узел стоит перед вторым подставным,
дескриптора которого у него нет, и цепочка срывается при установке: 2/5 * 3/12 = 1/10 попыток.
Остальные девять устанавливаются, 3/10 попыток, и каждая кончается честным узлом. Значит, среди
установленных цепочек подставной узел есть в каждой, а подставных входа и выхода нет ни в
одной, тогда как сам выбор, до установки, даёт 3/12 = 1/4: скрывая дескрипторы, два узла
забирают все входы и теряют выход. При -withhold 1 отказов нет, срывается 1/20 попыток, а среди
установленных цепочек у 1/19 подставные вход и выход и в 15/19 есть подставной узел. Цепочки
этих случаев тесты тоже перебирают.

Модель складывает виды так, будто подставные узлы одной цепочки связали свои цепочки. Соседние узлы
связывают их по общему каналу точно. Вход и выход связывают по запаздыванию установки: когда цепочки
устанавливаются по одной и следующая начинается, только когда установка предыдущей дошла до её
последнего узла, первое событие на выходе после события на входе принадлежит той же цепочке, и
точность top-1 по цепочкам, прошедшим оба узла, равна 1 по построению, а каждая такая связь
взаимная. ROC AUC при этом может быть ниже 1, потому что сравнивает пары разных цепочек: входы в 0,
310 и 320 мс и выходы в 300, 315 и 325 мс дают top-1 1 и AUC 17/18 (верная пара первой цепочки,
1/1.3, ниже неверной пары второго входа с третьим выходом, 1/1.015). Цепочка подставного входа с
честным выходом может при этом связаться с цепочкой честного входа, прошедшей подставной выход;
при своём клиенте у каждой цепочки такая ложная связь R не поднимает и не опускает: вид другой
цепочки называет позиции этой неверно или так же, как её собственный вид, а сложение, начатое с
собственного вида, сохраняет всё, что он знает. Измерение несёт одновременная установка нескольких цепочек: там связывание может ошибиться,
дать ничью или оказаться невзаимным, и R цепочки ниже, чем при сложенных видах, только если цепочка
прошла оба узла, а её не связали или связали не с той цепочкой. Разрыв определяется для одного способа
связывания, взаимного наибольшего без разрешения ничьих: способ, который разрешает ничьи случайно
или сопоставляет цепочки один к одному по всем парам, может связать цепочки, которые этот оставляет
несвязанными, поэтому разрыв описывает этот способ, а не свойство системы. Оценка «минус задержка» с
неопределённой оценкой -2 у исключённых пар поставила бы верную пару с задержкой больше 2 с ниже
исключённых: входы в 0, 1 и 3 с и выходы в 0.5, 1.2 и 5.5 с дали бы top-1 2/3 и AUC 7/9 вместо 1 и
17/18.

Комплект узла с сертификатом второго УЦ не проходит проверку по якорю. Такого узла нет ни в одном
зеркале, честные узлы к нему не продлевают, а зеркало, которое он отдаёт как вход, получает
отказ: в нём нет проверенного комплекта самого входа. Честному зеркалу тогда не хватает k узлов.
Если k не больше min(-missing, N - h), цепочки честных входов идут без этих узлов: доли цепочек с
подставным узлом и с подставными концами 0, срывов 0, отказов k/N у эха и k/(N - 1) у клиента
-peer с честным mailbox, который выбирает вход среди N - 1 узлов, кроме mailbox; иначе отказ
получает каждая попытка. Если сам mailbox из второго УЦ, его нет ни в одном зеркале, и отказ
получает каждая попытка клиента -peer. При N = 5, h = 3 и k = 1 это 1/5 отказов у эха и 1/4 у
-peer при -missing 1 и 2 и отказ на каждой попытке при -missing 0. Для эха при k < h это те же
доли, что даёт модель зеркал при -leftout N - k и -withhold k: N - k больше границы при любом
-missing, и подставной вход получает отказ. При k не меньше h и -missing не меньше N - k такой
-leftout укладывается в границу и пропустил бы подставной вход, поэтому модель второго УЦ
считается отдельно; тесты перебирают все цепочки до шести узлов при случайном и закреплённом
выходе. Узел скомпрометированного УЦ выбирается как любой другой: у эха доли равновероятного
выбора, 0 и 3/5 при k = 1, 1/10 и 9/10 при k = 2; у -peer доли закреплённого выхода (таблица со
столбцом mailbox выше).

Все строки, кроме доли отказов, точны по построению и проверяются без интервала. Отказ бывает
ровно тогда, когда входом выпал узел второго УЦ, поэтому интервал проверяет выбор входа, а саму
границу проверяют точные строки. Доля отказов это одно заявление теста, m = 1, допуск 0.05; в
число заявлений серий блока оно не входит. 3000 попыток дают ему точную мощность 0.999998 при
доле модели, а 673 попытки, которые даёт формула объёма ниже при m = 1, только 0.80: тест с ними
не проходил бы примерно при каждом пятом зерне. Клиент, которому входом выпал узел второго УЦ,
запрашивает у него зеркало; в тесте зеркало читается без HTTP, и этот запрос не моделируется.
Честный узел принимает входящий канал с любого адреса, как от клиента, поэтому то, что узел
второго УЦ не продлевает к честным узлам, держится только на том, что он следует протоколу:
отступивший от протокола узел может продлевать к честным, но только входом цепочки, которую
клиент собрал в обход своего выбора. Клиент -peer с закреплённым mailbox этим тестом не
проверяется: его доли выведены выше. На наборе ГОСТ проверяются все строки, кроме выборки.

Согласие с моделью в блоке 3. Доли и средняя R сравниваются с моделью эквивалентностью (раздел
«Сравнения»): допуск δ задаётся до серии, по умолчанию 0.05, как для AUC; m это число заявлений
блока без точных по построению; интервал на уровне 1 - 0.05/m, у доли интервал Уилсона, у
средней R нормальный. Единица у эха цепочка. У клиента -peer единица это процесс: вход
выбирается один раз на процесс, пересборка набирает ту же цепочку, а середины выбираются заново
не больше двух раз, поэтому R стороны берётся по первой цепочке процесса, пересборки в неё не
входят, а процессы с новым выбором середин приводятся отдельно; сторон на конфигурацию столько
же, сколько процессов, вдвое больше, чем разговоров. Средняя R заявляется только там, где
связывание точно по построению: один подставной узел в цепочке, соседние подставные узлы или
установка по одной. При одновременной установке средняя R приводится против модели как разрыв
связывания: единица там прогон (средняя R прогона, медиана по чистым прогонам, рядом доли
цепочек, прошедших оба узла, оставшихся несвязанными и связанных не с той цепочкой), и в число
заявлений она не входит. Число цепочек на конфигурацию это наибольшее по её заявлениям
max(30, ceil((σ (z_{1-0.025/m} + z_{0.9}) / δ)^2)), где σ это стандартное отклонение одного
наблюдения по модели, sqrt(p(1-p)) у доли и σ(R) у R: тогда при точной модели заявление проходит
с вероятностью около 0.8. При m = 14 и δ = 0.05 доле около 0.6 нужно 1690 цепочек, доле 0.2 нужно
1127, средней R эха при k = 1 нужно 810, средней R стороны -peer при честном mailbox и k = 1 нужно
1321 процесс, то есть 661 разговор. Рядом приводится отклонение в стандартных ошибках модели как
проверка согласованности. Список конфигураций, δ, m и число цепочек задаются до серии.

узел стоит выходом, 0.21: интервал Уилсона [0.183, 0.239] внутри [0.15, 0.25]. Цепочек с
подставным узлом 1089, 0.605: интервал [0.571, 0.638] внутри [0.55, 0.65].

Серии корреляции блока 1 идут с числом узлов, равным числу хопов, в порядке, который обвязка
задаёт сама: выбор цепочки в них не участвует. Обвязка запускает узлы и клиентов в одном
процессе и соединяет их через loopback, а не в кластере, поэтому сетевой задержки между ними
нет. Её узлы работают без сертификатов, с анонимными каналами между узлами, без ротации
онион-ключа и с выключенными ограничениями на один адрес, а последний узел возвращает каждое
сообщение эхом.

### Блок 4. Ключевой материал, нарушитель П5

Реализованный кооперативный этап: `lab -set keymem` ([#24](https://github.com/jimichi-org/jimichi/issues/24)).
В заданной серии оценены все 360 запланированных наблюдений, по 30 новых процессов на
набор/политику/точку, без исключений. Числа, происхождение бинарника и диагностика нагрузки
приведены в [README](../../README.ru.md#результаты-кооперативной-проверки-памяти-ключей).
Проверяется наблюдаемость во время инструментированной производственной нагрузки; модель П5
целиком не проверяется.

| Компонент | Метод |
|---|---|
| Нагрузка | новый процесс клиента подключается к трём настоящим узлам по аутентифицированным каналам, проверяет их пакеты под УЦ, отправляет `jimichi/keymem/v1` и требует точное эхо; производственные пути CryptoProvider, client, wire, link и relay |
| Выбранные секреты | три свежих 32-байтовых ключа ячейки, в порядке вход/середина/выход, возвращённые производственным `DeriveKey` с назначением `cell` и использованные в `NewAEAD`; других классов нет |
| Наблюдение | клиент добровольно вызывает `runtime/debug.WriteHeapDump` один раз; отдельный контроллер разбирает ограниченный поток и ищет совпадения только в Object payloads (`go-exported-object-payloads-v1`) |
| Политики | `none` и `all`, каждая фиксируется до выделения первого ключа дочернего процесса; ключи контроллера и узлов всегда под `all`; запрет дампов процесса включён в обоих условиях |
| Контрольные точки | `active`: эхо проверено, клиент открыт; `closed-now`: успешный `Client.Close` вернулся, намеренной задержки нет; `closed-1s`: не раньше монотонной секунды после этого возврата |
| Независимая единица | новый дочерний процесс и набор узлов на каждый снимок; контрольные точки не переиспользуют процесс или ключ |

При активном снимке исходные выбранные буферы имеют длину 32; после Close их безопасно проверяемые
длины равны нулю. Освобождённые байтовые представления не читаются. Зерно задаёт только перемешанное
расписание шести условий в каждом блоке повторов, а не криптографическую случайность. Принудительного
GC и переопределения GOGC нет; записываются счётчики GC и фактические задержки от Close до экспорта.
`closed-now` не означает нулевую задержку, а независимые точки не отслеживают жизнь одного ключа.

Контроли и оценка:

- Свежий положительный маркер должен совпасть в диапазоне своего выделенного Object; отдельная
  копия не удовлетворяет этому контролю. Независимый отрицательный маркер остаётся у контроллера и не
  должен совпасть.
- Эталоны ключей и рабочие байты потока находятся в защищённых буферах контроллера. Сырые экспорты,
  ключи, хэши секретов, адреса и фрагменты не сохраняются. Наблюдённые байты не подаются в криптографию.
- Оценка требует поддерживаемой среды, действующей защиты, успешных эха и жизненного цикла,
  полного структурного разбора с настоящим EOF, успешного выхода и очистки процесса и обоих контролей.
- Обрезанные, некорректные, ограниченные, неуспешные и неподдерживаемые наблюдения исключаются;
  числа совпадений и наличие ключа получают null. Недостигнутая или неприменимая диагностика
  остаётся null; недоступный результат не заменяется нулём.
- Указываются planned, started, evaluated, excluded, not_started и причины исключений.
  `planned = evaluated + excluded = started + not_started`; excluded включает незапущенные строки.
- Доля равна `trials_with_any_match / evaluated`. Для каждого хопа знаменатель тоже evaluated,
  а не утроенное evaluated. Рядом стоят planned и evaluated; пустой знаменатель даёт null.
  Сводки вхождений включают оценённые нули. Сводки покрытия и времени берут только оценённые
  строки с этим полем не null, включая достигнутые нулевые значения.

Эта версия даёт описательные числа и доли, без p-значений, доверительных интервалов и заявления
о превосходстве. Совпадения под `all`, отсутствие разницы и ненаблюдение допустимы.

Запускать стабильный оптимизированный бинарник на Linux/amd64, строго с Go 1.27.3 и работающим mlock.
Хост должен быть свободен от посторонней нагрузки; бинарник во время серии не пересобирать.
Выполненная заранее заданная полная серия:

```
lab -set keymem -suite c25519 -repeats 30 -seed 1 -rev eddddb226e7224140f8655b1566a55ce33f3ceda -out artifacts
lab -set keymem -suite gost -repeats 30 -seed 1 -rev eddddb226e7224140f8655b1566a55ce33f3ceda -out artifacts
```

Каждый вызов фиксирует обе политики и все три точки; `-repeats` допускает 1..100.
Применимы только `-set`, `-suite`, `-repeats`, `-seed`, `-rev`, `-out` и справка; флаги других
экспериментов и позиционные аргументы отклоняются. Ввода произвольной цели, снимка или образца
поиска нет. Точка входа Go: `keymem.Run(context.Context, keymem.Config)`, поля Suite, Repeats, Seed
и Revision ([lab/keymem](../../lab/keymem)).

Уникальный каталог под `-out` содержит только `manifest.json`, `trials.jsonl` и `summary.json`
(схема `keymem-cooperative-v1`). Строки сохраняют каждую запланированную попытку; сводка заново
вычисляется из них; свежие секреты и уничтоженные сырые потоки повторно не воспроизводятся.
Манифест записывает представление, ревизию, хэш бинарника с набором хэширования,
платформу/runtime, расписание, ограничения и действующую защиту. Попытка ограничена 60 с и
128 МиБ экспорта. Неподдерживаемая среда или недоступный mlock дают явные недоступные строки.
Код выхода 0 требует оценки каждой попытки и записи отчётов; 1 означает недоступную/неуспешную
серию или ошибку отчёта, 2 некорректные публичные аргументы.

`all` одновременно меняет выделение, блокировку, исключение из дампов и зануление. Основные mmap-буферы
не входят в Object payloads и при живых ключах, поэтому меньше совпадений может означать исключение
из представления, а не уничтожение. Отсюда не следуют вклад отдельной меры, эффективность запрета
дампов, покрытие всей кучи/процесса, стирание, срок стирания или защита от root. Копии, вызванные
экспортом/компилятором, неотличимы от библиотечных; преобразованные состояния и пропуски экспорта
runtime не обнаруживаются ([LIMITATIONS](LIMITATIONS.md), [CRYPTO](CRYPTO.md), "Известные дыры").

Более широкие сценарии ниже не реализованы и не измерены, отложены за v0.4.0
([#192](https://github.com/jimichi-org/jimichi/issues/192)). Существующие переключатели `-keymem`
и `-harden` узла/клиента этих измерений не дают.

| Отложенный сценарий | Предполагаемое наблюдение |
|---|---|
| Внешнее получение памяти узла во время сессии | доля наблюдений известных ключей с мерами защиты памяти и без них, вне кооперативного представления |
| Внешнее получение памяти после сессии | остаточные представления и наблюдаемое временное окно в выбранном представлении памяти |
| Поиск на диске, в swap и в образе | найден ли выбранный ключевой материал |
| Кража ключей узла при заданном возрасте записанных служебных ячеек | доля записанных установок, чей слой открывается, в зависимости от времени от записи до кражи, с ротацией онион-ключа и без неё |
| Память клиента `-peer` во время разговора | ключ личности, цепочки ратчета и право забора F |
| Память клиента `-peer` после смены ключей | ключ записи после открытия и прежний ключ цепочки после шага ратчета |
| Контейнер клиента после закрытия | оставшиеся представления ключа тома |

### Блок 5. Контейнер клиента, нарушители П5 и П6

([#20](https://github.com/jimichi-org/jimichi/issues/20)).

| Сценарий | Метрика |
|---|---|
| Статистика шифротекста | NIST STS, энтропия, критерий хи-квадрат; о скрытом томе не свидетельствуют |

NIST STS, энтропия и хи-квадрат о скрытом томе не свидетельствуют: они могут показать, что файл
отличается от случайных данных, но не что один том неотличим от двух.

Для П6 файл пишется один раз (ARCHITECTURE, "Одна запись"), поэтому его снимки ожидаются
одинаковыми байт в байт; то, что файловая система и диск хранят сверх файла, это граница
(LIMITATIONS). Результат будет заявлен как измеренный.

### Блок 6. Производительность и стоимость примитивов

Статус: реализовано частично. Замеры go test -bench есть для генерации ключа, согласования ключа,
подписи, проверки подписи, одного слоя AEAD ячейки, хэша транскрипта, вывода ключей хопа и
сцепления двух согласований, ключа из пароля и пары из секрета на обоих наборах (crypto/suite),
для шифрования ячейки и снятия слоя на c25519 (wire), для рукопожатия KK и одной записи
хэш-ратчета на обоих наборах (e2e). Обвязка выдаёт круговую задержку для цепочек из двух и
более узлов. В плане
([#118](https://github.com/jimichi-org/jimichi/issues/118)): замер
установки на узле с одним и с двумя онион-ключами, пропускная способность узла при насыщении,
полезная скорость на клиента, задержка для цепочки из одного узла (обвязка не принимает меньше двух
хопов) и вклад mlock (у обвязки и у замеров нет переключателя мер защиты памяти).

| Что меряем | Как |
|---|---|
| Согласование ключа | go test -bench, наносекунд на операцию, ГОСТ против X25519 |
| Установка в льготный период | наносекунд на установку на узле с одним и с двумя онион-ключами, ГОСТ против X25519: второй ключ стоит второго согласования, и платится оно только в льготный период, 22 минуты каждого часа на стенде |
| Снятие слоя | наносекунд и аллокаций на ячейку |
| Пропускная способность узла | ячеек в секунду при насыщении, на 1, 2 и 4 ядрах |
| Задержка по хопам | один, два, три узла; p50, p95, p99 |
| Вклад mlock | те же метрики с блокировкой памяти и без |
| Сквозной слой | go test -bench, наносекунд на рукопожатие KK обеих сторон и на запись хэш-ратчета, ГОСТ против X25519 |
| Ключ из пароля | go test -bench (BenchmarkPasswordKey), стена и процессорное время на вызов, Argon2id против PBKDF2 со Стрибогом-512 |
| Пара из секрета | go test -bench (BenchmarkDerivePair), стена и процессорное время на вызов, ГОСТ против X25519 |

У сквозного слоя два замера в e2e. BenchmarkKK меряет одно рукопожатие обеих сторон: две сессии
с проверкой карточки, kk1 и kk2. BenchmarkRatchetStep меряет одну запись с телом 368 байт: шаг и
Seal у отправителя, шаг и Open у получателя. Записанных замеров пока нет, более ранних для
сравнения тоже: слой новый. Их числа это измерение в плане, и публикуются они только из
записанного прогона.

У привязки каждого выводимого ключа к транскрипту, набору и версии схемы переключателя нет, как
нет его у метки повтора установки и у кадра подтверждения канала: сборка без неё была бы второй
схемой вывода ключей, то есть путём понижения защиты. Её вклад не меряет ни один блок. Замеры
crypto/suite берут её части по отдельности: хэш транскрипта установки аутентифицированного
узла, с ключом личности (BenchmarkNewContext; клиент считает его по одному на хоп, узел по
одному на каждый онион-ключ, который он держит; рукопожатие канала хэширует свой транскрипт
другой длины, отдельно он не замеряется),
согласование под контекстом (BenchmarkAgree),
пять значений, которые хоп выводит после согласования: ключ установки, ключ ячейки, метка
повтора и два смещения counter (BenchmarkDeriveHopKeys), и сцепление двух согласований
аутентифицированного канала (BenchmarkMixKey). В релизе v0.2.0, последнем без привязки, для
сравнения есть только замер согласования.

Цена ключа из пароля это два числа на вызов: стена и процессорное время всего процесса
(ядро-секунды, user + sys по getrusage; на системах без getrusage только стена). Argon2id идёт в
четыре полосы на своих горутинах, поэтому его процессорное время около четырёх стен, а PBKDF2
однопоточный. Число итераций C_GOST набора ГОСТ подобрано одноразовым замером на машине стенда
так, чтобы ядро-секунды на догадку совпадали с Argon2id в пределах 0,8-1,25. Это равенство цены
на нашем коде в Linux-контейнерах стенда, а не у нарушителя: тот же код вне контейнера,
оптимизированный Стрибог и прежде всего GPU и специализированное железо, где PBKDF2 не нужна
память, считают догадку быстрее, и эта цена не измерена. У DerivePair набора ГОСТ число
кандидатов зависит от секрета, поэтому замер перебирает 64 секрета по кругу и даёт среднее;
худший случай, 128 отвергнутых кандидатов, меряет отдельный замер в crypto/gost. Записанных
замеров пока нет, их числа публикуются только из записанного прогона.

### Блок 7. Неразличимость ячеек, нарушитель П2

Статус: реализовано, серия в плане ([#23](https://github.com/jimichi-org/jimichi/issues/23)). Набор
`cmd/lab -set cover` прогоняет различитель ячеек (раздел «Неразличимость трафика») на канале
клиент-вход; чисел пока нет.

Наблюдатель видит моменты кадров на канале клиент-вход в обе стороны и отличает ячейку с сообщением
от фоновой по моментам ячеек потока и ответов на них. Вход цепочки видит на этом канале те же
моменты и не видит признака фоновой ячейки, который лежит внутри последнего слоя (ARCHITECTURE,
«Формат ячейки»), поэтому тот же различитель доступен и ему, и различимость, найденная здесь, есть и
у входа; что вход может узнать сверх этих признаков, блок не меряет.

| Фактор | Уровни |
|---|---|
| Режим клиента | add-1x: немедленный, фоновая ячейка каждые 200 мс; fixed-2x: постоянная скорость, слот каждые 100 мс. При среднем интервале сообщений 200 мс у обоих уровней около десяти ячеек в секунду на поток, половина с сообщением: одна цена в полосе и близкие размеры групп. Немедленный режим без фона уровнем не является: фоновых ячеек нет, AUC не определена |
| Набор примитивов | c25519 на трёх хопах; ГОСТ на двух и трёх, больше слой установки ГОСТ не вмещает |
| Клиент | только без -peer (LIMITATIONS) |
| Узлы | пересылают сразу, без отправки по своим часам (узлы стенда kind шлют по своим часам): признак r_idx определён, а ответ выхода на ячейку с сообщением уходит после её обработки, на фоновую сразу (LIMITATIONS) |

Разметка ячеек:

- Обвязка оборачивает провайдер каждого клиента; узлы получают провайдер без обёртки. Обёртка
  запоминает последний ключ ячейки, который клиент выводит при установке цепочки, то есть ключ
  выхода, и метит только Seal на экземпляре AEAD, созданном на этом ключе, и только с associated
  data ячейки данных на месте выхода (11 байт: версия, вид, counter, номер хопа). Метка это старший
  бит поля длины внутри последнего слоя, признак фоновой ячейки. Ячейки с сообщением и фоновые
  проходят обёртку одним путём.
- По длине метить нельзя: на c25519 при трёх хопах открытый текст слоя установки входа и последнего
  слоя ячейки данных одной длины, 446 байт (494 - 32 - 16 и 494 - 3 · 16), и первый байт слоя
  установки читался бы как ячейка с сообщением. Слои установки запечатываются на ключах установки и
  до помеченного экземпляра не доходят; тест обёртки проверяет этот случай явно.
- Второй экземпляр на ключе выхода или Seal на нём с другими associated data делает разметку потока
  несогласованной.
- Кадры вперёд это [установка, ячейки данных...]: кадр k + 1 несёт метку k. Ячейка метится до записи
  в канал, поэтому меток столько же, сколько кадров данных, или на одну больше, если последняя
  запись не прошла при закрытии клиента; лишняя метка в конце не используется.
- В каждом прогоне метки сверяются с кадрами каждого потока, а число меток с сообщением с числом
  сообщений, переданных клиентам, минус отброшенные расписанием (messages - dropped). Прогон с
  расхождением помечается label_mismatch и не входит ни в обучение, ни в медианы, ни в сравнения;
  сводка их считает (label_mismatch_runs), и clean_runs в сводке блока 7 их тоже не считает.

Признаки ячейки, в секундах, в этом порядке:

| Признак | Определение |
|---|---|
| g_prev | интервал от предыдущей ячейки данных потока |
| g_next | интервал до следующей ячейки данных потока |
| dev | \|g_prev - m\|, m это медиана g_prev ячеек потока в окне; медиана своя у каждого потока и считается без меток |
| r_next | от ячейки до первого кадра назад строго после неё |
| r_idx | от ячейки до k-го кадра назад, если это k-я ячейка данных потока: выход отвечает на каждую ячейку данных одной ячейкой, клиент принимает ответы строго по номерам, а без отправки по своим часам узла назад к клиенту идут только ответы. С часами узла признака нет |

- Ячейки различителя это кадры данных в окне наблюдения; соседние кадры и ответы берутся и вне окна.
  Ячейка без какого-либо признака (первая и последняя ячейка данных потока, нет кадра назад после
  неё, нет k-го кадра назад) не входит ни в обучение, ни в проверку, ни в D и TV; их число в строке
  (undefined_cells).
- По определению признаки не связаны линейно: dev это модуль отклонения, а не g_prev минус
  постоянная потока. r_next и r_idx определены по-разному, но совпадают, когда ответ на ячейку
  отмечен строго после неё и между ними нет другого кадра назад; если на обучении они совпали у всех
  ячеек, r_idx не используется по правилу различителя, строка уровня в выводе набора это печатает, а
  строка отчёта несёт (unused_features).
- Ответ на ячейку на loopback приходит через десятки микросекунд после неё, поэтому набор перед
  прогонами меряет шаг монотонных часов хоста и не запускается при шаге больше 10 мкс: при более
  грубых часах ответ отмечался бы тем же отсчётом, что и ячейка (LIMITATIONS). Шаг записан в каждой
  строке и в сводке (clock_step).
- При постоянной скорости моменты ячеек задаёт расписание, а не сообщения, поэтому для g_prev,
  g_next и dev ожидается уровень угадывания. r_next и r_idx несут ещё и момент ответа выхода, а он у
  узлов без отправки по своим часам зависит от вида ячейки: AUC выше 0.5 при постоянной скорости
  может идти от него, а не от момента отправки. Какой признак разделяет классы, показывает
  feature_auc.

Обучение, проверка и нулевые уровни:

- На каждом уровне сначала идут -train обучающих прогонов (по умолчанию 5), затем -repeats прогонов
  серии. Зёрна обучающих прогонов выводятся из -seed отдельным потоком и не совпадают ни с одним
  зерном повтора серии: обучающие прогоны не делят с серией интервалов сообщений и фаз клиентов. У
  обучающей строки repeat это номер обучающего прогона, и ни с одной строкой серии она не парна.
- Различитель обучается один раз, на ячейках чистых обучающих прогонов уровня без расхождения меток,
  вместе; каждый прогон серии проверочный. Строка обучающего прогона несёт AUC, при которой этот
  прогон исключён из обучения. Пилот это набор с -repeats 0: по AUC его обучающих прогонов до серии
  задаются s и число прогонов.
- Эквивалентность заявляет только уровень постоянной скорости: вопрос серии в том, скрывает ли
  постоянная скорость момент отправки при узлах, которые пересылают сразу (заявленную в THREAT_MODEL
  настройку с отправкой узлов по своим часам набор не меряет), а от add-1x ожидается различимость,
  и у него в сводке нет ни границ квантилей для коридора, ни вердикта. Поэтому каждый запуск набора
  даёт одно заявление, а m (-claims) это число запусков серии блока 7, чей вердикт читается
  (например, c25519 на трёх хопах и ГОСТ на двух и трёх дают m = 3); m задаётся до серии планом
  заявлений, а не по пилоту.
- D и TV считаются по g_prev ячеек с сообщением против фоновых: g_prev от обучения не зависит,
  поэтому они есть и у уровня без направления. Нулевой уровень: круговой сдвиг меток каждого потока
  на число, равномерное от 1 до n - 1 (n ячеек потока), из потока зёрен прогона, одна выборка на
  прогон; поток из одной ячейки не сдвигается. Рядом для сравнения перестановка меток всех ячеек
  прогона (ks_permuted, tv_permuted).

| Где | Что |
|---|---|
| строка прогона, cells-cover-*.json | role (training или claim); конфигурация, зёрна, ревизия и загрузка хоста, как в блоке 1, и шаг часов (clock_step); messages, dropped, cells, bandwidth_multiplier, payload_labels, label_mismatch; payload_cells, cover_cells, undefined_cells; lda_auc с интервалом BCa по потокам, feature_auc по каждому признаку, unused_features, degenerate (missing_class у прогона без одного из классов, training_missing_class, training_no_feature, training_equal_means у прогона без направления обучения); ks_distance, ks_null, ks_permuted, tv, tv_null, tv_permuted; признаки закрытия цепочек и лимитов узлов, как в блоке 1. Интервал BCa описательный: его покрытие на нулевых прогонах не проверено, и выводы на нём не строятся, они идут по распределению AUC прогонов и коридору |
| сводка, summary-cover-*.json | у набора шаг часов, s и m; у каждого уровня: заявляет ли он эквивалентность (equivalence_claim); обучающие прогоны, всего и использованные, причина отсутствия направления и неиспользованные признаки; runs, broken_runs, limited_runs, label_mismatch_runs, clean_runs, degenerate_runs; медианы по чистым прогонам серии: lda_auc, ks_distance, ks_null, tv и tv_null с интервалом по порядковым статистикам на уровне 0.95, минимум и максимум AUC, медианы AUC по признакам; число прогонов, на которых стоят медиана AUC и медианы D и TV (lda_auc_runs, ks_runs): вырожденный прогон не даёт AUC, прогон без одного из классов не даёт и D с TV, а печать сводки помечает медиану по одному прогону; у уровня постоянной скорости нижняя граница s-квантиля и верхняя граница (1 - s)-квантиля AUC прогонов серии на уровне 1 - 0.05/m (auc_corridor_low, auc_corridor_high) при s (-corridor, по умолчанию 0.2) и m (-claims, по умолчанию 1) и вердикт, лежат ли они в коридоре [0.45, 0.55] (раздел «Сравнения»); точность при базовой ставке с TPR и числом фоновых ячеек; медиана множителя полосы |

## Статистика

- Цель для полной серии ([#23](https://github.com/jimichi-org/jimichi/issues/23)): не менее 30
  чистых повторов на точку (без закрытых цепочек и без сработавших лимитов узла, в отчёте это
  clean_runs). Опубликованная серия предварительная, повторов на точку в ней меньше. Окно
  наблюдения открывается, когда потоки начинают слать, поэтому установка цепочек в него не
  входит; отдельный прогрев не отбрасывается.
- Серии идут при остановленном кластере kind и без сборки на хосте: параллельная нагрузка
  сбивает тайминги и занижает AUC отдельных прогонов. В таблицах приводится медиана.
- Внутри прогона у AUC есть доверительный интервал 95 процентов: бутстрэп BCa по потокам, 10000
  выборок. По повторам сводка даёт медиану, минимум и максимум; сводка блока 7 даёт к медианам AUC,
  D, TV и нулевых уровней D и TV интервал по порядковым статистикам на уровне 0.95 (раздел
  «Сравнения»), сводки блока 1 дадут его вместе с полной серией
  ([#23](https://github.com/jimichi-org/jimichi/issues/23)).
- Конфигурации и атаки сравниваются по одному соглашению, раздел «Сравнения» ниже.
- У атаки связывания блока 1 нет обучения. Различитель ячеек (раздел «Неразличимость трафика»)
  обучается на отдельных обучающих прогонах той же конфигурации, которые идут до серии со своими
  зёрнами из отдельного потока и в неё не входят, и проверяется на каждом прогоне серии. Калибровка
  степени анонимности по апостериорному распределению обучается на других чистых прогонах той же
  конфигурации и проверяется на отложенном прогоне; обучение никогда не берёт прогон с тем же зерном
  повтора, что у отложенного (такие прогоны делят интервалы сообщений, раздел «Сравнения»).
  Обучаемая атака связывания, когда она появится, будет обучаться и проверяться на разных выборках,
  с разделением по времени и без утечки признаков.
- Узел закрывает цепочку, если counter нарушил порядок (копия, пропуск, шаг назад, скачок, у
  выхода первый прямой counter не тот, что в его слое установки), ячейке не хватило места в
  очереди в любую сторону, назад пришла ячейка другого вида или такая, которую он не может
  обернуть, выход не смог зашифровать ответ по любой причине, кроме длины (ответ длиннее ячейки
  уходит фоновым под тем же номером), ячейку не удалось записать в канал к следующему узлу или
  обратно к клиенту. Запись в канал, который узел сам закрыл, закрывая цепочку, повторно не
  учитывается. Клиент закрывает цепочку при ответе с негодным заголовком, ответе, который не
  открылся, ответе не по порядку, ответе сверх числа записанных ячеек и кадре канала от входа,
  который не открылся. Такой кадр может создать любой на линии между клиентом и входом, поэтому
  отклонённый кадр не указывает на вход. Поток тогда останавливается раньше конца прогона, и его
  трассы короче. Поток, чья цепочка закончилась, больше не передаёт клиенту сообщений, поэтому
  messages, drop_rate и unanswered разорванного прогона считаются только до её закрытия.
- Строка отчёта несёт relay_broken_circuits (сумма закрытий, замеченных каждым узлом: одну цепочку
  могут посчитать несколько узлов), broken_flows (клиенты, отклонившие ответ или кадр канала) и
  по каждому потоку flow_closed и flow_closed_after: закрылась ли цепочка до конца прогона, по
  данным клиента и по любой причине, и через сколько после старта потоков ("" для открытой).
  Из полей клиента цепочка, которую закончил узел или противоположная сторона, видна в
  flow_closed, а не в broken_flows.
- Строка несёт также relay_timed_out (истёкшие сроки рукопожатия, установки и записи),
  relay_expired (цепочки, закрытые по простою или возрасту) и relay_refused (соединения и
  установки, в которых узлы отказали), в сумме по узлам. Прогон ограничен, если хоть одно из них
  ненулевое: то, что он потерял, он потерял из-за ограничения узла, а не из-за проверяемой
  конфигурации. Истёкший срок записи закрывает цепочку, поэтому он виден и в relay_timed_out, и в
  relay_broken_circuits.
- Прогон разорван, если хоть один из признаков закрытия ненулевой. В сводке runs считает все
  прогоны, broken_runs разорванные, limited_runs ограниченные (прогон может быть и тем, и
  другим), clean_runs те, что ни то ни другое; медианы, размах и ci_degenerate_runs берутся по
  чистым прогонам. Если таких нет, эти поля null; медиана задержки null и тогда, когда у чистых
  прогонов нет ни одного замера. Строка с одним чистым прогоном даёт его значения, а не медиану,
  и печать сводки помечает её.
- relay_dropped_cells считает ячейки, которые узлы отбросили: ячейки, чей слой не открылся, с
  неразборчивым заголовком, для неизвестной цепочки, служебные ячейки неудавшейся или отклонённой
  установки (слой не открылся, копия уже виденной установки, полный кэш меток, занятый
  идентификатор, канал уже несёт цепочку, следующий узел недоступен), ответы длиннее ячейки
  (вместо них уходит фоновый ответ под тем же номером), ячейки, оставшиеся в очереди закрытой
  цепочки, и, когда узел пересылает сразу, ячейки к следующему узлу и ответы выхода, запись
  которых пришлась на канал, который этот узел уже закрыл сам. Запись, не удавшаяся по другой
  причине, закрывает цепочку и учитывается в relay_broken_circuits, а не здесь.

### Сравнения

Одно соглашение для полной серии блока 1 ([#23](https://github.com/jimichi-org/jimichi/issues/23)),
блоков 2 ([#116](https://github.com/jimichi-org/jimichi/issues/116)), 3
([#117](https://github.com/jimichi-org/jimichi/issues/117)) и 7. Процедуры реализованы один раз в
lab/metrics (stats.go) и проверены тестами с ответами, посчитанными вручную; сводка блока 7 вызывает
их (Уилкоксон, Холм, интервал квантиля, эквивалентность), сводки остальных блоков будут вызывать их
вместе со своими сериями.

Процедуры:

- Равенство значений: a и b считаются равными, если |a - b| не больше 1e-9 max(|a|, |b|),
  потому что одно и то же число, полученное разной арифметикой, расходится в последних битах.
  Правило действует для ничьих и нулевых разностей в критериях Манна-Уитни и Уилкоксона, в
  размерах эффекта, в расстоянии Колмогорова-Смирнова и корзинах полной вариации, а у различителя
  ячеек для постоянных признаков и равных средних классов. Оценки атаки связывания (ROC AUC,
  точность top-1, места верного входа, калибровка) сравниваются точно: при расчёте они округлены
  до 1e-9. Оценки различителя ячеек тоже сравниваются точно, без округления: равные строки
  признаков дают побитно равные оценки. Правило не транзитивно, поэтому группа равных начинается с
  наименьшего значения и берёт все значения в пределах 1e-9 от него. Значения с большим смещением
  (абсолютные метки времени, счётчики) в процедуры не подаются: 1e10 + 5 и 1e10 по этому правилу
  равны. Интервалы и вердикт эквивалентности сравнивают значения точно.
- Критерий Манна-Уитни, две независимые выборки: x из n значений и y из m. U это число пар, где
  значение x больше значения y, плюс половина пар с равными значениями, по всем nm парам; U/(nm)
  читается как AUC. Двусторонний p это доля разбиений объединённой выборки на группы из n и m
  значений, у которых |U - nm/2| не меньше наблюдаемого; равные значения получают средний ранг.
  Пока min(n, m)(n+m) не больше 5000 (в том числе до 50 значений в каждой группе), p точный:
  распределение U по всем C(n+m, n) разбиениям считается подсчётом сумм рангов. Выше порога
  нормальное приближение с поправками на ничьи и на непрерывность:
  z = max(|U - nm/2| - 0.5, 0) / sqrt(nm/12 (n+m+1 - S / ((n+m)(n+m-1)))), где S это сумма
  t^3 - t по группам из t равных значений, и p = 2(1 - F(z)), F это функция стандартного
  нормального распределения. При больших группах ничьих приближение занижает p (семь значений 0 и
  1 в каждой группе: 0.045 против точного 0.103), и с ростом выборки это не проходит, если ничьи
  образуют редкие значения меньшинства. Поэтому выводы делаются только по точному p: если серия
  выходит за порог, порог поднимается до анализа (подсчёт растёт как квадрат min(n, m)(n+m)).
- Критерий Уилкоксона для знаковых рангов, пары (x_i, y_i). Пары с равными x_i и y_i
  отбрасываются, остаётся n' разностей d_i = x_i - y_i; их модули ранжируются со средними
  рангами, W это сумма рангов положительных разностей. Двусторонний p это доля из 2^n'
  расстановок знаков, у которых |W - n'(n'+1)/4| не меньше наблюдаемого: точно, подсчётом сумм
  рангов, при n' не больше 100, иначе
  z = max(|W - n'(n'+1)/4| - 0.5, 0) / sqrt(n'(n'+1)(2n'+1)/24 - S/48), где S та же сумма по
  группам равных модулей, и p = 2(1 - F(z)).
- Размер эффекта, от -1 до 1. У Манна-Уитни это дельта Клиффа: (число пар с x > y минус число
  пар с x < y) / (nm), то есть 2U/(nm) - 1. У Уилкоксона парная ранговая бисериальная корреляция
  (Kerby, 2014): (W - W') / (W + W'), где W' это сумма рангов отрицательных разностей; её знак
  всегда на той стороне, куда отклоняется W, а для независимых выборок та же мера и есть дельта
  Клиффа. Дельта Клиффа на парных данных описывала бы перекрытие двух распределений и могла бы
  указать в сторону, противоположную критерию. Величина для обеих мер по порогам Romano и др.
  (2006): модуль меньше 0.147 ничтожная, меньше 0.33 малая, меньше 0.474 средняя, иначе большая.
- Поправка Холма для семейства из k сравнений: p упорядочиваются по возрастанию,
  p(1) <= ... <= p(k); скорректированный p(j) это наибольшее (k - i + 1) p(i) по i <= j, но не
  больше 1. Гипотеза отвергается, если её скорректированный p не больше 0.05.
- Интервал для доли: x из n попыток, p = x/n, z квантиль стандартного нормального распределения
  уровня 1 - α/2 при уровне интервала 1 - α. Интервал Уилсона:
  (p + z^2/(2n) -+ z sqrt(p(1-p)/n + z^2/(4n^2))) / (1 + z^2/n); при x = 0 нижняя граница 0,
  при x = n верхняя 1. В отличие от p -+ z sqrt(p(1-p)/n) он не схлопывается в точку при x = 0 и
  x = n и не выходит за [0, 1] (Brown, Cai, DasGupta, 2001). Пример: 600 из 1000 на уровне 0.95
  дают [0.5693, 0.6299].
- Интервал для среднего: x̄ -+ z s/sqrt(n), s выборочное стандартное отклонение с делителем
  n - 1; если все значения равны, интервал это само значение. Квантиль нормальный, а не
  Стьюдента: при размерах блока 3 (от 533 цепочек) t шире меньше чем на половину процента (на
  0.45 процента при n = 533 и на 0.24 процента при n = 1000 на уровне для 14 заявлений); для 30
  прогонов точки он не годится, там t шире на 8.8 процента на том же уровне и на 4.4 процента на
  уровне 0.95.
- Интервал для квантиля по порядковым статистикам, без допущения о виде распределения:
  n независимых значений одного распределения, x_(1) <= ... <= x_(n), K ~ Binom(n, q), уровень
  интервала 1 - α. Нижняя граница x_(l) с наибольшим l, при котором P(K <= l - 1) <= α/2, верхняя
  x_(u) с наименьшим u, при котором P(K >= u) <= α/2; покрытие 1 - P(K <= l - 1) - P(K >= u) не
  меньше 1 - α, при ничьих тоже. Если такого номера нет, граница не определена: при пяти прогонах
  интервала медианы уровня 0.95 нет (P(K = 0) = 1/32). Точка это квантиль с линейной
  интерполяцией, у медианы обычная медиана. Пример: 20 прогонов, медиана, уровень 0.95: x_(6) и
  x_(15), покрытие 1 - 2·21700/2^20, около 0.9586. Границы двух квантилей ограничивают долю
  прогонов: нижняя граница квантиля s и верхняя граница квантиля 1 - s, обе на уровне 1 - α,
  вместе верны с вероятностью не меньше 1 - α, и если они внутри коридора, то доля прогонов ниже
  коридора и доля выше не больше s каждая. При уровне 0.95 и s = 0.2 это x_(1) и x_(n) от 17 до
  25 прогонов (0.8^17 около 0.0225, 0.8^16 около 0.0281) и x_(2) и x_(n - 1) от 26 до 33; для
  s = 0.1 обеих границ нет, пока прогонов меньше 36 (0.9^n > 0.025).
- Вердикт эквивалентности: «эквивалентно», если интервал целиком лежит внутри значения модели
  плюс-минус допуск (края включаются), иначе «не показано»; неопределённый интервал и
  бесконечный допуск вердикта не дают. «Не показано» не значит, что величина отличается от
  модели.
- Объём для заявления эквивалентности: при стандартном отклонении одного наблюдения σ по
  модели, допуске δ, m заявлениях и мощности π это
  n = max(30, ceil((σ (z_{1-0.025/m} + z_{(1+π)/2}) / δ)^2)); меньше 30 не берётся, там
  нормальное приближение не держится. Заявление проходит, когда отклонение оценки от модели не
  больше δ - z_{1-0.025/m} SE, а при точной модели и нормальной оценке это бывает с вероятностью
  2F(δ/SE - z_{1-0.025/m}) - 1. Это нормальное приближение: у доли около 0 или 1 точная мощность
  интервала Уилсона на несколько пунктов ниже (0.74 вместо 0.8 у доли 0.1 при 634 цепочках).
  Пример: σ = 0.5, δ = 0.05, m = 1, π = 0.8 дают 1051.

Правила:

- Критерии двусторонние, уровень 0.05 на семейство после поправки Холма. Семейство это
  сравнения, отвечающие на один вопрос блока, например все уровни одного фактора против базовой
  конфигурации.
- Метрики прогона (AUC и подобные) ограничены, распределены не нормально и часто упираются в
  край: AUC прогона нередко ровно 1. Поэтому критерии ранговые, без допущений о распределении, а
  p точный: если серия выходит за порог любого из двух критериев, порог поднимается до анализа.
- Прогоны парные, если делят потоки случайных чисел. Зерно повтора r в cmd/lab выводится только из
  -seed и r (обучающие прогоны блока 7 берут зёрна из своего потока и ни с чем не парны), поэтому
  прогоны с одним -seed и одним номером повтора, из одного набора или из разных запусков, делят
  поток интервалов сообщений и поток фаз клиентов. Фаза это остаток от деления общего случайного
  числа на расписание уровня, поэтому у уровней с одним расписанием фазы совпадают, у уровней с
  разными расписаниями совпадают лишь у части потоков, а у уровня без расписания фаз нет; фазы часов
  узлов у каждого прогона свои. Такие прогоны сравниваются парно по номеру повтора, критерием
  Уилкоксона, по парам, где оба прогона чистые; число отброшенных пар приводится рядом, так как пара
  остаётся, только если выжили оба уровня. Пара делит случайные числа, но не время: уровни набора
  идут один за другим, и дрейф загрузки хоста пара не вычитает. Так же парно сравниваются две
  величины одного прогона, например две атаки на одних каналах. Прогоны с разными -seed независимы
  и сравниваются критерием Манна-Уитни. В блоке 2 неудачные и закрытые попытки остаются в бинарной
  величине, условия паруются по блоку повторов, а детектор внутри прогона калибруется полным
  перебором кодов, как описано в этом блоке.
- p приводится только вместе с размером эффекта, значимая, но ничтожная разница так и
  называется.
- В семейство Холма входят только сравнения, где результат это отвержение нулевой гипотезы.
  Сравнение, исход которого точен по построению (у Манна-Уитни одно и то же значение во всех
  прогонах обеих групп, у Уилкоксона равные значения в каждой паре; процедура помечает его как
  degenerate), и неопределённое сравнение (пустая группа) не тестируются и в семейство не входят.
  Блок 2 является явным исключением: фиксированное семейство десяти позиций сохраняет вырожденное
  p=1, недоступные позиции занимают 1 при поправке, затем их результаты возвращаются в null.
- Согласие с моделью и равенство угадыванию из незначимого p не выводятся: при малом числе прогонов
  незначимый p ничего не показывает, а поправка Холма только облегчила бы такое заявление. Попадание
  доли в +-2 SE модели это то же непринятие нулевой гипотезы, поэтому отклонение в SE подаётся как
  проверка согласованности, а не как согласие. Согласие заявляется как эквивалентность: до серии
  блок задаёт допуск и заявляет согласие, только если интервал 95 процентов для измеренной величины
  целиком лежит внутри значения модели плюс-минус допуск; при m таких заявлениях в блоке интервалы
  берутся на уровне 1 - 0.05/m. Для AUC допуск по умолчанию 0.05, коридор [0.45, 0.55]. Величина,
  которую блок сравнивает с коридором, при точном угадывании должна лежать заметно внутри коридора:
  сложенная AUC прогона max(AUC, 1 - AUC) сдвинута шумом вверх и при малом числе потоков может
  лежать выше 0.55 при любом числе прогонов. Она же должна ограничивать долю прогонов, которые
  различают, а не только центр: и смесь прогонов с AUC 0.2 и 0.8, и 22 прогона с AUC 0.5 рядом с 8
  прогонами с 0.8 дают медиану 0.5, но не угадывание. Величину, её интервал, допуск и число
  прогонов, с учётом шага самой величины, блок задаёт до серии; долю различающих прогонов
  ограничивают интервалы квантилей (процедуры выше), сводка блока 7 приводит эти границы квантилей
  при s и m, заданных флагами, и вердикт для уровня постоянной скорости; в сводках остальных блоков
  они в плане вместе с сериями ([#23](https://github.com/jimichi-org/jimichi/issues/23)).
- Степени анонимности и эффективный размер приводятся описательно: заявлений различия и
  равенства по ним нет, пока для них не определён интервал. Степень по рангам считается по всем
  прогонам конфигурации вместе и интервала по прогонам не имеет, а значения апостериорной степени
  у отложенных прогонов зависимы через общее обучение.
- В блоке 3 интервалы определены выше: Уилсон для долей, нормальный для средней R, допуск
  задаётся до серии (по умолчанию 0.05), объём по правилу для эквивалентности при мощности 0.8
  (блок 3, «Согласие с моделью в блоке 3»). m это число заявлений эквивалентности блока; буква k в
  блоке 3 занята числом подставных узлов. Заявления эквивалентности в семейство Холма не входят:
  их кратность учтена уровнем 1 - 0.05/m. Критерии согласия (хи-квадрат, точный биномиальный)
  согласие не показывают и в блоке 3 не применяются: отклонение от модели видно в отклонении в
  SE, а вид каждой цепочки сверяется с её маршрутом напрямую.
- Наименьший достижимый точный p равен 2/2^n' у Уилкоксона и 2/C(n+m, n) у Манна-Уитни при
  равных группах или без ничьих; при неравных группах с ничьими нулевое распределение бывает
  несимметричным, и пол опускается до 1/C(n+m, n). При пяти прогонах на группу это 2/252, около
  0.0079, и в семействе больше чем из шести сравнений ни одна разница не пройдёт первый порог
  Холма 0.05/k. При пяти парах это 2/32 = 0.0625, и парное сравнение не значимо даже в одиночку;
  нулевые разности уменьшают n' и поднимают пол. Поэтому пилот из пяти прогонов на точку служит
  только для расчёта объёма серии, выводы делаются по серии.
- Объём серии, в плане ([#23](https://github.com/jimichi-org/jimichi/issues/23)): перед серией
  пилот из пяти прогонов на точку на той же ревизии кода. Мощность считается повторной выборкой
  из прогонов пилота, где одна группа сдвинута на 0.05 AUC от ближнего края отрезка [0, 1], тем
  же точным критерием, что пойдёт в серию, на первом пороге Холма, для парных сравнений по числу
  ненулевых разностей. Объём это
  наименьшее число прогонов с мощностью 0.8; в серии на точку идёт больше из 30 и этого объёма,
  прогоны пилота в серию не входят.

## Сравнение с аналогами

В плане: таблица по одинаковым признакам для Tor, Session, SimpleX, Briar и этой работы.
Признаки: постоянный размер ячейки, фоновый трафик, состояние на узле, отрицаемость, набор
примитивов, опубликованные оценки задержки. Из свойств отрицаемости в этой работе сейчас есть
отрицание факта отправки при постоянной скорости и отправке узлов по своим часам, отсутствие ключей
после сессии и офлайн-отрицаемая аутентификация между клиентами, показанная подделкой, а не
измеренная (THREAT_MODEL); контейнер клиента ([#20](https://github.com/jimichi-org/jimichi/issues/20))
реализован, а измерение его свойства в плане (блок 5). Числа чужих
систем будут взяты из их документации и публикаций, свои будут измерены. Прямое сравнение
производительности проводиться не будет: условия разные, это будет указано явно.

   дашбордом ([#21](https://github.com/jimichi-org/jimichi/issues/21)).
2. Наблюдатель: атака связывания идёт без защиты и с каждой мерой по очереди. От фонового
   трафика поверх сообщений падения AUC не ожидается: в предварительной серии с фоном он
   оставался 1.000, а отправка узлами по своим часам снизила его до медиан 0.44-0.67 против
   0.94-1.00 в остальных строках таблицы README; показать, что атака падает до угадывания, эти
   прогоны не могут ([README](../../README.ru.md)). Показ результата атаки вживую в плане вместе с
   дашбордом ([#21](https://github.com/jimichi-org/jimichi/issues/21)).
3. Кривая «множитель полосы против AUC». На опубликованном графике интервалов нет;
   доверительные интервалы по прогонам в плане вместе с полной серией
   ([#23](https://github.com/jimichi-org/jimichi/issues/23)).
4. Кооперативная проверка ключей ячейки клиента (`lab -set keymem`, блок 4), с `none` и `all`
   в трёх независимых точках. Заданная серия завершена ([результаты](../../README.ru.md#результаты-кооперативной-проверки-памяти-ключей)); ненаблюдение точных байтов в оценённых
   Object payloads стирания не доказывает. Широкие сценарии памяти/диска/истории остаются
   неизмеренными ([#192](https://github.com/jimichi-org/jimichi/issues/192)); известные копии
   библиотек перечислены в [CRYPTO](CRYPTO.md), раздел "Известные дыры".
5. Контейнер ([#20](https://github.com/jimichi-org/jimichi/issues/20)): `jimichi vault init` и
   `jimichi vault show`, один пароль открывает том легенды, другой второй том; различитель
   блока 5 в плане. Результаты NIST STS о скрытом томе не свидетельствуют: они показывают только
   отсутствие статистической структуры в шифротексте.
6. Таблица стоимости: ГОСТ против X25519 по замерам go test -bench и круговая задержка для цепочек
   из двух и трёх узлов; остальное из блока 6 в плане
   ([#118](https://github.com/jimichi-org/jimichi/issues/118)).
7. Подделка переписки: `cmd/lab -set deny` на обоих наборах. Получатель, у которого есть только
   свои ключи, строит транскрипт, который проходит ту же проверку, что настоящий, а подделка со
   свежим ключом вместо ключа получателя её не проходит. Показывается вместе с границами: только
   офлайн, без засвидетельствованного транскрипта, без метаданных ([CRYPTO](CRYPTO.md),
   "Отрицаемость").
